## 1. 読み方と前提

### 1.1 企画書の要旨（依頼文より）

- 事務所の PC で「計画と通報」、現場のスマホで「点検と飛行記録」、戻って PC で「日誌と報告」を完結させる。
- 「実務で使える」5 条件: ①前日までに PC で計画〜DIPS 通報、②電波なしの現場でスマホだけで点検・飛行記録、③飛行終了時点で様式1〜3 の日誌が揃う、④許可書・技能証明・日誌をスマホで提示、⑤案件ごとの作業報告書を発注元に渡せる。
- 技術前提: Next.js（Vercel, soraban.futuretec.jp）・Neon・Neon Auth のまま、スマホは PWA、DIPS 通信はサーバー側のみ・トークン非保存。
- リリース 4 段階: ①現場が回る → ②通報がつながる → ③報告まで閉じる → ④社外に出す。DIPS API はクライアント ID の発行待ちなので、手入力で現場を先に回す。
