# Sprint 7: 判定の現行法令対応（飛行禁止法 1,000m・DID から工業専用地域を除外・データ出典と確認日）

> 親文書：`docs/spec.md` §13「第1段階」（§13.3 判定の現行法令対応）／ `docs/00_NORTH_STAR.md` §0.1.2
> 前提：Sprint 1〜6 が完了していること。DB は使わない（Neon 移行は Sprint 8）。
> ※ Next.js は破壊的変更を含むため、実装前に `node_modules/next/dist/docs/` を参照（`apps/web/AGENTS.md`）。

## スプリント分割の判断

推奨案では「判定の現行法令対応」と「Supabase → Neon の DB 層置き換えの土台」を 1 スプリントにしていたが、次の理由で分け、本スプリントは判定の法令対応だけを扱う。Neon の土台は Sprint 8 とする。

1. **安全側の修正を基盤工事に待たせない。** 飛行禁止法は現行実装が過小判定（敷地境界から 1,000m 以内でも green になりうる）であり、最優先で直す。DB の準備（秘密情報の置き場、CI の方式、ブランチ運用）はユーザーの決定待ちの事項が多く（spec §13.8 未決 6〜8）、同じスプリントに入れると法令対応の完了まで止まる。
2. **大きさ。** 法令対応だけで機能 5 件・契約 20 項目前後になり、Sprint 6 と同程度。Neon の土台（接続層、マイグレーション、既存スキーマ移植、Supabase 撤去、CI ジョブ）を加えると約 2 倍になる。
3. **検証の手段が異なる。** 法令対応は単体テストと Playwright で閉じる。DB の土台は PostgreSQL コンテナを使う CI ジョブの新設が必要で、evaluator の確認手順も別になる。
4. **依存がない。** 判定データは本スプリントでは静的データのまま扱い、データの読み込み口を関数で分けておく。DB 化（Sprint 13）ではその読み込み口だけを差し替える。

## 実装する機能

- **A. 小型無人機等飛行禁止法の周辺地域 1,000m（2026-07-14 施行の改正）**
  - 対象施設を出典付きの構造化データ（例：`packages/regulations/data/small-drone-law/facilities.json`）にする。各施設に、名称、種別（防衛関係施設・原子力事業所 等）、根拠告示（名称・日付・URL）、敷地形状（ポリゴン）とその出典（`geometrySource`：告示区域図のトレース／OpenStreetMap／中心点のみ 等）、周辺距離（1,000m）、yellow 幅（既定 300m）、確認日、確認者を持たせる。
  - 判定は敷地境界からの距離で行う。敷地内または境界から 1,000m 以内 → red。1,000m 超〜1,000m＋yellow 幅以内 → yellow（「おおむね 1,000m。告示の区域図で要確認」）。それ以外 → green。
  - 敷地形状が未収録で中心点しかない施設は、推定敷地半径を足した保守側の距離で判定し、note に「敷地形状未収録のため概算」と出す。
  - 美保基地は敷地ポリゴンで持つ（中心点＋300m／1,500m の扱いを廃止）。yellow の文言から「空港周辺の進入表面」を外す（空港は `evaluateAirports` が扱う）。
  - 鳥取県・島根県で告示により指定を確認できた施設を収録する。美保基地以外の候補（島根原子力発電所、陸上自衛隊米子駐屯地・出雲駐屯地、航空自衛隊高尾山分屯基地 等）は告示で確認できたものだけを収録し、確認した施設名・確認できなかった施設名・確認日をデータの README に残す。
  - 規制の要約・本文・note・地図の凡例・PDF の「300m」を「おおむね 1,000m」に改め、改正後は周辺地域での飛行そのものが罰則の対象である旨を要約に入れる。
  - 申請支援の手続きに「施設管理者の同意 ＋ 都道府県公安委員会への事前通報（飛行の 48 時間前まで）」（例：`small-drone-law-consent-notice`）を追加し、対象施設が red／yellow のとき表示する。出典 URL・法的根拠・確認日を持たせる。期限は文言で示し、開庁日計算の対象にしない。
- **B. DID データの令和2年国勢調査ベースへの更新と本番での読み込み**
  - DID を令和2年国勢調査ベースに更新する（入手元候補：国土数値情報 A16 の令和2年版、e-Stat 統計GIS の境界データ「人口集中地区（令和2年）」）。
  - 鳥取県（31）・島根県（32）分を本番でも読み込めるようにする（推奨：リポジトリに同梱し静的 import。ユーザー承認が前提＝未決 2）。形状の単純化はしない（境界が縮むと過小判定になる）。座標の丸めは小数 6 桁まで。合計容量が 10MB を超える場合は実装を止めてオーケストレーターに報告する。
  - 地図の DID レイヤーと凡例の出典表記を新データに合わせる。
  - プリセットの curated DID フラグ（例：米子市役所の `airspace_did`）は、エンジンの DID 判定が「未確認」のときだけ使い、「該当」「非該当」のときは上書きしない。
- **C. 人口集中地区から工業専用地域を除く扱い（国土交通省告示第435号、2026-07-01 から）**
  - 工業専用地域のポリゴンを市町村単位で収録し（例：`packages/regulations/data/industrial-exclusive/`）、収録範囲の台帳（市町村コード、収録状況＝収録済み／未収録、出典、基準時点、確認日）を持つ。DID と工業専用地域が重なる市町村から優先して収録する。
  - 入手元候補（優先順。ライセンス・更新時点を確認して台帳に記録）：①各市町の都市計画図（用途地域）、②国土交通省都市局「都市計画決定 GIS データ」（G空間情報センター／国土数値情報「都市計画決定情報」）、③国土数値情報「用途地域」（A29）、④とっとりWebマップ・マップonしまね。
  - `evaluateDid` の分岐：
    1. DID データなし → `unknown`（現行どおり、未確認）
    2. DID 外 → green（非該当）
    3. DID 内・当該市町村の工業専用地域が収録済み・工業専用地域の内側（境界から既定 10m 以上内側）→ green（非該当：工業専用地域のため DID の飛行許可は不要。告示第435号。空港等周辺・150m 以上・飛行の方法の承認は別途、と note に明記）
    4. DID 内・収録済み・工業専用地域外、または境界から 10m 未満 → red（該当。境界付近の場合はその旨を note に出す）
    5. DID 内・当該市町村の工業専用地域が未収録 → red（該当として扱う）。note と UI に「工業専用地域の除外：未確認（データ未収録）。工業専用地域内であれば DID の飛行許可は不要。市の用途地域図で確認」と表示する（縮退表示）
  - 分岐 3 では診断に `airspace_did` を付けず、DID の三値は「非該当」とする。画面・PDF・履歴の DID 表示は「非該当（工業専用地域）」と区別して示す。
  - 判定は地点単位である旨（飛行範囲全体が工業専用地域内かは別途確認）を分岐 3 の note に含める。
  - 地図に工業専用地域（DID 除外）レイヤーを追加し、凡例に出典を表示する。
- **D. データ出典と確認日の台帳・表示**
  - 判定に使うデータセット（DID、工業専用地域、空港、飛行禁止法の対象施設、公園、史跡、県条例の対象施設）の台帳（例：`packages/regulations/data/sources.json`）を置く。各件に、ID、名称、提供元、URL、ライセンス、基準年・版、取得日、確認日、確認者、収録範囲を持たせる。
  - 各 `RegulationWithStatus` に、使ったデータセット（ID・名称・基準年・確認日）と、反映済みの法令改正（根拠と施行日。例：告示第435号 2026-07-01、改正飛行禁止法 2026-07-14）を付ける。
  - 規制カードと地点判定 PDF・申請支援 PDF に、データ名・基準年・確認日と、反映済みの改正（施行日）を表示する。
- **E. 証跡と互換性**
  - `ENGINE_VERSION` を上げる。証跡 ID の入力に、使用データセットの ID と確認日を含める（データ更新で証跡 ID が変わる）。
  - 規制 ID を変更・追加する場合も、既存の `soraban:history:v1` の履歴（旧 ID・旧カテゴリーを含む）が壊れずに読み込め、復元できる。
