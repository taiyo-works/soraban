## 0. 要点

- **A（変更の影響）**: 通報の記録がある計画を訂正するとき（訂正の画面）と訂正した後（計画の画面）に、「何が変わったか」と「確認し直すこと」を項目ごとに出す。確認し直すことは、soraban に既にある仕組みが返す事実だけで組み立てる: 通報の指紋の違い（DIPS の通報の変更が要りうる）、判定が古くなった理由、計画の確認のやり直し、登録した許可・承認との照合の結果の変化、飛行禁止法の手続きの記録の見直し。
- drone-ops の「許可の範囲の確認（10 開庁日）」「同意の取り直し（目安 3 日）」「48 時間前まで」の**日数は持ち込まない**（申請の段取りに読める・※要再確認）。
- **C（変更前後の表示）**: 版の一覧で「変わった項目名」に加えて、項目ごとの変更前・変更後の値を出す。技能証明書の番号は伏せる。

## 1. 現状（【確認】）

- 判定の古さ: `server/ops/plan-logic.ts` の `snapshotFreshness`（`input_changed`・`permits_changed`・`engine_changed`・`data_changed`・`procedures_changed`）。
- 通報: `packages/dips/src/status.ts` で指紋が違えば `change_review`。範囲の訂正でも指紋が変わる（19-1b）。
- 確認: 版に結びつくので、訂正の後はやり直し。
- 版の一覧: `components/ops/versions.tsx` の `VersionList` は版番号・操作・訂正者・日時・理由・**変わった項目名**（`service.ts` の `changedFields`）だけ。版の `data` は `record_versions` に全部ある。

## 2. 実装する機能

- **機能A: 変更の影響の純粋関数** — 2 つの版の `data`（と、通報の記録の時点の指紋）から、変わった項目（日時・所要時間・範囲・高度・機体・操縦者・特定飛行の形態・許可の結び付け など）と、項目ごとの「確認し直すこと」の種類（`report_change`＝DIPS の通報の変更を検討、`rejudge`、`reconfirm`、`permit_match_changed`、`small_drone_law_review`）を返す。判定エンジンを呼ばない。
- **機能B: 訂正の画面の予告** — 通報の記録がある計画の訂正の画面で、保存の前に「この訂正で確認し直すこと」を一覧で出す（保存は止めない）。
- **機能C: 計画の画面の表示** — 訂正の後、計画の通報のタブに「前回の通報から変わった項目」と「確認し直すこと」を出す。各行は作業の場所（通報の作業台・判定・確認・手続きの記録）へ 1 タップ。既存の次にやること（`change_report` など）と重複しない形にする（同じ行を 2 回出さない）。
- **機能D: 変更前後の表示** — 版の一覧の各版に「変更の内容を見る」。開くと項目名・変更前・変更後を並べる。範囲は頂点の数・面積の要約で示す（座標の全文を並べない）。技能証明書の番号は「（伏せています）」。取消の版は「取消」と理由。

## 3. スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

- [ ] **K-1（単体）** 変更の影響の関数が、日時・範囲・機体・操縦者・形態・許可の結び付けのそれぞれを変えたときに、該当の項目と確認し直すことを返す。何も変えない訂正（理由だけ）は空を返す。範囲の頂点を 1 つ動かすと `report_change` を返す（指紋の規則と一致）。［単体］
- [ ] **K-2（単体）** 返す値に日数・期限日が含まれない。「許可」「申請」の語を含むラベルが無い（許可・承認の照合は「登録した許可・承認との照合の結果が変わりました」の形）。［単体＋文言の検査］
- [ ] **K-3（訂正の予告）** 通報の記録がある計画の訂正で日時を変えると、保存の前に予告の一覧が出て、保存はできる。通報の記録が無い計画では予告を出さない。［E2E-DB］
- [ ] **K-4（計画の画面）** 訂正の後、通報のタブに変わった項目と確認し直すことが出て、各行から作業の場所へ 1 タップで移る。同じ内容の次にやることと二重に出ない。［E2E-DB］
- [ ] **K-5（変更前後）** 版の一覧で「変更の内容を見る」を開くと、項目名・変更前・変更後が出る。技能証明書の番号の文字列がページに 0 件。範囲は要約で、座標の小数の並びが出ない。［E2E-DB］
- [ ] **K-6（記録は変わらない）** 版の表・ハッシュチェーン・`verify_record_chain`・判定のスナップショット・`ENGINE_VERSION` に差分 0（表示だけ）。［DB テスト・git］
- [ ] **K-7（権限）** 変更前後の表示は、版の一覧を見られる役割だけが見られる（既存の権限のまま）。他の組織の版は 404。［DB テスト］
- [ ] **K-8（回帰）** `data-testid` の基準の差分 0。既存の E2E・単体・DB テストがすべて通る。

## 6. やらないこと

- 手続きの期限の日数の表示（48 時間前・3 日・10 開庁日。※要再確認、境界）。
- 変更の影響による保存の停止。
- 判定エンジンの変更。

## 7. 安全側の考え方

- 「確認し直すことはありません」とは書かない。空のときは一覧そのものを出さない（無いと言い切る文を出さない）。
- 変わった項目の判定は、版の `data` の比較と指紋の比較の両方で行い、どちらかが違えば「変わった」とする。
