## 0. 要点

1. 飛行エリア（範囲）は、通報の中心の項目の 1 つ（DIPS の `flyRoute`: GeoJSON の文字列。`Circle`（中心＋半径 m）または `Polygon`（3 点以上））。いまのアプリは**点＋半径（円）だけ**で、多角形は作れない。通報の整形も**円だけ**に対応し、多角形は「DIPS の地図で描いてください」と案内している（`packages/dips/src/messages.ts` の `route_polygon_unsupported`）【確認】。
2. このスプリントは、**どの地点でも、地図の上で範囲（多角形・円・複数）を描き、頂点を直し、取り消し・やり直しができ、座標を確認し、DIPS の形式に変換して送信前に確認できる**地図の編集部品を作る。スマホ（タッチ）と PC（マウス）の両方。**判定は補助。範囲は判定の入力にしない（代表点だけ渡す）**。
3. 品質基準は最上位（UI/UX・視覚）。designer の工程を省かない。

## 2. DIPS の形式（ガイドライン 1.10 版。`dips-fpr-guideline-findings.md` §3・§5。ページはガイドライン）

| 項目 | 内容 | 状態 |
|---|---|---|
| 飛行の経路 `flyRoute` | **GeoJSON 形式の文字列**（飾り（線種・色・透過率）は無視）。飛行範囲も含む（項番 16） | 【確認】 |
| ジオメトリタイプ | `Circle` または `Polygon`（項番 17） | 【確認】 |
| 円 | `radius`（メートル）。サンプルでは radius が geometry でなく properties にある（p53）。レスポンス側は geometry 内（p60） | 置き場所は※要再確認。コードは設定で切り替え |
| 多角形 | 構成点が 3 点以上。**終点は始点と同じ座標をサーバー側で生成**（項番 23）→ 送るときに閉じた環にするかは※要再確認 | 【確認】/※要再確認 |
| 座標系 | 代表点は十進法・度表記・**世界測地系**（項番 19） | 【確認】 |
| 構成点の上限、複数のジオメトリ（複数の範囲）を 1 つの `flyRoute` に入れられるか | **記載なし**（findings 本文） | **※要再確認**（検証環境で確かめる。クライアント ID が前提） |
| 飛行する高度 `flightAltitude` | 数値 1〜999（m、AGL）、計画全体で 1 つ | 【確認】 |
| 飛行日時 | 計画の開始・終了（日時の形式は `yyyyMMdd□HHmm`〔検索側〕）。タイムゾーンの指定の記載なし | 【確認】/※要再確認 |

**設計への含意**: 範囲ごとの高度・時間帯は DIPS の項目に無い（高度は 1 つ）。範囲ごとの高度・時間帯は**利用者の控え（内部のメモ）**として持ち、DIPS へは**最大高度と飛行日時の全体**を送る。複数の範囲の送り方（1 つの `flyRoute` に複数のジオメトリか、1 つに統合した外周か）が確定するまで、**1 計画 = 1 つのジオメトリを送る**ことを既定にし、複数の範囲は内部では持つが送信前に「DIPS に送るのは 1 つです。統合するか、計画を分けてください」と確認させる（仕様確認後に変更）。

## 3. 設計

### 3.1 データ

- 計画に**飛行エリアのジオメトリ**を持たせる（`flight_plans` の新しい列または版のデータ。マイグレーション）。形: 範囲の配列（各範囲: 種類 `circle`／`polygon`、頂点または中心＋半径、名前、メモ（高度・時間帯））。**既存の `latitude`・`longitude`・`radius_m` は残し、代表点（円の中心、または多角形の重心）として保つ**（判定・通報の既存の処理と互換）。既存の計画（点＋半径）は、移行で 1 つの円の範囲に読み替える。
- **判定への渡し方**: 判定は代表点だけを使う（山陰。判定は補助）。範囲全体での判定は範囲外。
- 版の履歴・スナップショット: 範囲は計画の版に含まれ、訂正は新しい版（既存の規則）。

### 3.3 変換と送信前の確認

- **変換**: 範囲 → DIPS の `flyRoute`（GeoJSON 文字列）。円は `Circle`、多角形は `Polygon`。頂点は小数 6 桁、WGS84。環の閉じ方・半径の置き場所は設定（`packages/dips` の既存の切り替え）で、検証環境で確かめるまで既定は「現行」（円: properties）。**頂点数の上限は不明のため、アプリ側の暫定の上限（例: 100 頂点。決定は 19 の着手時）を置き、超えたら警告**（※要再確認）。
- **送信前の確認**: 通報の確認画面（Sprint 17 の作業台、27 の送信画面）に、**地図の上で送る図形を色つきで表示**（頂点の番号、半径、面積、頂点数）、座標の一覧、飛行高度・日時との組み合わせ、「DIPS に送る形」（折りたたみ。JSON を見せる）。「この範囲は DIPS に送る内容です。地図は参考で、実際の飛行範囲の責任は利用者にあります。」を固定で出す。
- **不正な図形**: 自己交差する多角形、3 点未満、面積 0、極端に大きい範囲は、その場で警告し、送れない状態にしない（警告は出すが、利用者が確認して進める）か、送信不可にするかを DIPS の仕様確認後に決める（※要再確認）。自己交差は警告。

### 3.4 画面（スクロールなしで見えるもの）

- 地図の編集画面は、375×812 で**地図が画面の主役**（高さの 55% 以上）。上部に最小の状態（範囲の数・頂点数）、下部に操作バー（選ぶ・多角形・円・追加・取り消し・やり直し・完了）。シートで頂点の一覧・範囲の一覧を開く。1280×800 では地図を左、一覧とプロパティを右の列。
- 計画の作成・訂正の画面に、**地図で範囲を決める手順**を入れる（座標の手入力は「詳細」に移す）。
- 判定の結果・レイヤーは補助として、地図の上のレイヤーの切り替えで見せる（山陰以外では「この地域の規制は確認していません」の帯）。

19-1 データ（マイグレーション、型、代表点、読み替え）と変換（`packages/dips`）。19-2 地図の編集部品（描画・編集・取り消し）。19-3 計画の入力・確認画面への組み込み、送信前の確認、全国の確認。各 PR で designer → evaluator。

## 6. ユーザーに聞くこと

1. **範囲の分割**（M-10）は要りますか（削れる）。
2. 複数の範囲を 1 回の通報で送りたいか、計画を分けるか（DIPS の仕様が確定するまでは、1 計画 1 図形が既定）。
3. 範囲ごとの高度・時間帯は、控え（内部のメモ）でよいか（DIPS の項目に無い）。
