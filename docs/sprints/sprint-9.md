## 目的と位置付け

点検の現場では、飛行地点を住所で探せない（山林・農地・河川敷・港湾など）か、住所で探せても町字の代表点にしか合わないことが多い。判定の正確さは地点の正確さに依存するため、地点を早く正しく指定できるようにする。North Star §0.1.7 の 1（手間か誤りを減らす）・2（山陰で自社の点検が飛ぶ場所で使う）に当たる。判定ロジックと証跡 ID の計算は変えない（判定の入力は従来どおり緯度経度だけ）。

ユーザー承認済みの内容（spec §13.8.1、2026-10-19 追記）のうち、本スプリントで扱うのは ①ブラウザの位置情報による現在地ボタン、②公的データによる住所検索（アドレス・ベース・レジストリ → 国土地理院の 2 段）、③地図の長押し（スマートフォン）・右クリックによる地点指定。Yahoo! JAPAN の住所検索による補完は、2026-10-19 のユーザー決定により本スプリントから外し、LINEヤフーへの利用条件の確認後の後続とする（下記「後続」）。Google のジオコーディングは、規約上 Google の地図以外（本アプリは MapLibre）と組み合わせられないため使わない。

## 実装する機能

- **A. 公的データによる住所検索（鳥取県・島根県）**
  - A-1（最初に行う計測。結果は `packages/regulations/data/address/README.md` に残す）：アドレス・ベース・レジストリの鳥取県（31）・島根県（32）について、町字・住居表示・地番の各件数、うち座標を持つ件数、取得ファイルの容量、索引にした後の容量を計測する。地番は市町村ごとの「位置付き件数／全件数」を記録する。取得日とデータの版を記録する。
  - A-2：町字と住居表示（座標付き）を検索用の静的索引（例：`packages/regulations/data/address/`）にしてリポジトリに同梱し、サーバー側で静的 import する（Sprint 7 の DID と同じ作法）。地番（座標付き）は、町字・住居表示と合わせて 10MB 以内に収まる場合だけ同梱する。収まらない場合は地番を収録せず、A-1 の計測結果を後続の判断材料として残す。住所データの合計が 10MB を超える構成にはしない。
  - 取り込みは abr-geocoder の取り込み処理か、CSV を直接読む変換スクリプト（例：`scripts/build-address-index.ts`）で行う。再実行で同じ索引ができ、取得元 URL・取得日・版を索引のメタデータに書く。
  - 照合：都道府県名・郡名の省略、全角・半角、漢数字と算用数字、「丁目」「番地」「番」「号」「-」「の」の表記揺れ、「大字」「字」の有無を吸収する。一致した階層の深い順（地番・住居 → 街区 → 町字 → 市町村）に並べる。
  - 公的データの検索は実行時に外部 API を呼ばない。
- **B. 検索の順序と表示**
  - `/api/geocode` を ①同梱索引 → ②国土地理院の住所検索 の順にする。②は①で結果がないか、①が町字止まりのときに呼ぶ。②が応答しない・エラーでも①の結果は返す（②のタイムアウト既定 3 秒）。
  - 各結果に、出典（`abr`・`gsi`）、一致した階層（`parcel`・`residence`・`block`・`machiaza`・`city`・`prefecture`・`unknown`）、表示名、緯度経度を持たせる。画面には出典名と精度の説明（例：「町字の代表点。実際の飛行地点は地図で指定してください」）を出す。
  - 応答の形は、後続で出典（例：`yahoo`）を足せる形にしておく（出典の値を列挙型で 1 か所に定義する）。
  - 住所検索の近く（または画面下部のデータ出典欄）に「出典：アドレス・ベース・レジストリ（デジタル庁）を加工して作成」と国土地理院の出典を表示する。データセット台帳（`packages/regulations/data/sources.json`）にこの 2 件を追加する。
- **C. 現在地ボタン**
  - 地図上に「現在地」ボタンを置く。押したときだけ `navigator.geolocation.getCurrentPosition` を 1 回呼ぶ（高精度、タイムアウト 10 秒、キャッシュ不使用）。`watchPosition` は使わない。ページを開いただけでは位置を取得しない。
  - 取得できたら、地図をその位置に移し、精度（メートル）を半径とする円と候補の印、「現在地（精度 約 N m）」「この地点で判定」「取消」を表示する。**自動では判定しない。**「この地点で判定」を押したときに `goToLocation` で判定する。
  - 精度が 100m を超える場合は「位置の精度が低い。地図で位置を確かめ、長押し（右クリック）で直してください」と表示する。
  - 失敗時：許可されていない →「位置情報の利用が許可されていません。ブラウザの設定で許可するか、住所検索・地図の長押しで指定してください」。取得できない・時間切れ → それぞれの理由と同じ案内。どの失敗でも、それまでの地点と判定結果は変えず、自動で再試行しない。
  - `navigator.geolocation` がない、または HTTPS でない環境では、ボタンを無効にして理由を表示する。
  - 応答ヘッダーで位置情報を自サイトに許可する（`Permissions-Policy: geolocation=(self)`。既存の設定と矛盾しないことを実装時に確認する）。
- **D. 地図の長押し・右クリックによる地点指定**
  - タッチ：指 1 本で 500ms 以上押し、その間の移動が 10px 以内なら、その位置を地点に指定する。2 本目の指が触れた・地図が動いた・10px を超えて動いた場合は取り消す。
  - マウス：右クリック（MapLibre の `contextmenu`）でその位置を地点に指定し、地図上ではブラウザの右クリックメニューを出さない。
  - 指定後は従来のクリックと同じく `goToLocation` で判定し、「地図で指定しました」と短く表示する。
  - 単タップ（タッチ端末）での地点指定を続けるかは未決 1。
- **E. プライバシー**
  - 現在地は端末内（ブラウザ）で地図の表示と候補の印にだけ使う。「この地点で判定」を押すまで、サーバー・外部 API に送らない。localStorage・Cookie・IndexedDB に現在地や精度を書かない。
  - 「この地点で判定」を押した後は、他の地点と同じく判定のために座標をサーバーに送り、履歴と（Sprint 8 の）`evidence_log` に残る。その際、「現在地から指定した」こと、精度、取得時刻は送らず、記録しない。
  - 現在地ボタンの近くに「現在地はこの端末の中で地図の表示に使います。『この地点で判定』を押したときだけ、判定のために座標を送ります」と表示する。
  - 判定の入力と証跡 ID の計算に、住所検索の出典や指定方法を含めない。

## 地番しかない地域での限界

- 山陰の農地・山林・河川沿いの多くは住居表示がなく、住所は地番で表される。地番の位置は公共座標系の登記所備付地図がある地域にしかなく、公図（任意座標系）の地域では位置がない。さらに本スプリントでは、容量の上限により地番を収録できない場合がある。この場合、住所検索は町字の代表点までしか一致せず、代表点は実際の飛行地点から数百 m 以上離れることがある。
- 判定（DID、飛行禁止法の 1,000m、公園・史跡など）は地点の数百 m の違いで結果が変わりうる。代表点での判定を飛行地点の判定として使わないよう、画面で精度を示し、長押し・右クリック（または座標入力）で実際の地点を指定する流れを用意する。これが D の主な目的である。

- [ ] 3. （単体）国土地理院への `fetch` を失敗させても、同梱索引の結果が返る。同梱索引で街区以上の一致がある入力では国土地理院を呼ばない。

### C. 現在地

- [ ] 6. （E2E）位置情報を許可し座標を与えたコンテキストで現在地ボタンを押すと、地図がその位置に移り、精度の円と「現在地（精度 約 N m）」が表示される。この時点では `/api/check`・`/api/diagnose`・`/api/geocode` への通信がない。
- [ ] 7. （E2E）続けて「この地点で判定」を押すと、与えた座標（小数 6 桁）で判定が行われ、緯度・経度の入力欄に反映される。
- [ ] 8. （E2E）位置情報を許可しないコンテキストで現在地ボタンを押すと、許可されていない旨と案内が表示され、それまでの地点と判定結果が変わらない。
- [ ] 9. （単体）`POSITION_UNAVAILABLE`・`TIMEOUT` のそれぞれで所定の文言になり、自動で再試行しない。精度 150m で低精度の表示になる。`watchPosition` を呼ばず、ボタンを押す前に `getCurrentPosition` を呼ばない。

### D. 長押し・右クリック

- [ ] 10. （E2E）タッチを有効にしたコンテキストで地図上の一点を 600ms 押すと、その位置が地点になり判定が行われる。300ms で離した場合は長押しとして扱われない。
- [ ] 11. （単体）長押しの判定が、押している間の 20px の移動、2 本目の指、地図の移動のそれぞれで取り消される。
- [ ] 12. （E2E）デスクトップのコンテキストで地図を右クリックすると、その位置が地点になり、ブラウザの右クリックメニューが出ない。

### E. プライバシーと回帰

- [ ] 13. （E2E）現在地を取得し「取消」を押した後、localStorage・Cookie に現在地の座標と精度がない。現在地から判定したときの `/api/check`・`/api/diagnose` の要求本文に、精度・取得時刻・指定方法の項目がない。
- [ ] 14. （E2E）現在地ボタンの近くに、現在地の扱いの説明文が表示されている。
- [ ] 15. （単体）同じ座標について、住所検索・現在地・長押し・座標入力のどれで指定しても証跡 ID の計算入力が同じ。
- [ ] 16. 既存の E2E（`e2e/reliability.spec.ts`・`e2e/sprint7.spec.ts`）と Sprint 8 の DB ジョブを含む CI がすべて緑で、`pnpm typecheck`・`pnpm lint`・`pnpm test`・`pnpm build` が通る。左クリックでの地点指定が従来どおり動き、全画面・全 PDF に免責文が残っている。

## 後続：Yahoo! JAPAN ジオコーダによる補完（LINEヤフーへの利用条件の確認後）

2026-10-19 のユーザー決定により本スプリントから外した。位置付けと、計画時に確認した条件だけを残す。スプリントへの組み込みは、下記のユーザー作業 2 の結果が出てから planner が改めて計画する（spec §13.6「後続の候補」）。

- **位置付け**：公的データ（アドレス・ベース・レジストリ・国土地理院）で結果がないか、番地付きの入力で町字止まりのときだけ呼ぶ補完。キー（`YAHOO_APP_ID`）が未設定なら一切通信しない。
- **当初案から移した契約の内容**：Yahoo! を呼ぶ条件、エラー・タイムアウト時に公的データの結果を返すこと、応答をキャッシュしないこと（同じ入力で 2 回呼ぶ）、Yahoo! が有効なときだけ所定のクレジットを画面下部に出すこと、Yahoo! が返した住所文字列を履歴・DB に残さないこと、キーをブラウザに渡さないこと、住所が LINEヤフーに送られる旨の表示。
- **地番を Neon に置く案**（本スプリントで地番を同梱できなかった場合）も、後続の計画で扱う。
- **ユーザー作業**：
  1. 会社の Yahoo! JAPAN ID でアプリを登録し、Client ID を取得する。

### 計画時に確認した Yahoo! ジオコーダ API（YOLP）の条件（2026-10-19）

| 項目 | 確認結果 |
|---|---|
| エンドポイント | `https://map.yahooapis.jp/geocode/V1/geoCoder`（GET）。必須は `appid`（Client ID）。`output=json`、住所階層 `al`（1 都道府県〜4 丁目・番地相当）、`ar`、`recursive`（https://developer.yahoo.co.jp/webapi/map/openlocalplatform/v1/geocoder.html ） |
| 回数制限 | 1 アプリケーション 1 日 5 万回まで。超えると利用制限の対象、超える利用は有償の YOLP Premier。短時間の大量アクセスも制限されうる（https://developer.yahoo.co.jp/webapi/map/ 、https://developer.yahoo.co.jp/webapi/map/faq.html ） |
| クレジット表示 | 必須。所定の HTML（テキスト。A〜D の 4 種から選ぶ）を改変せず、アプリケーションの下部に置き、API ドキュメントへのリンクにする。CSS で色を変える・極端に小さくするのは禁止。サイト内で最も目立つ要素にしない（https://developer.yahoo.co.jp/attribution/ ） |
| 保存・キャッシュ | 「YOLPにより提供される情報を、意図して保存（キャッシュを含みます）し、または、ユーザーに対して意図して保存（キャッシュを含みます）させてはならない」（LINEヤフーが別途認めた場合を除く）。常に最新の情報を取得する（https://developer.yahoo.co.jp/webapi/map/ ） |
| 商用・社内利用 | Web API は原則「利用者自身の便宜をはかる非商用目的」。ただし商用サイトや企業の利用をすべて禁じるものではなく、問い合わせ窓口に相談する（https://support.yahoo-net.jp/PccDeveloper/s/article/H000011080 ）。YOLP は「限られた人、コンピュータによるアクセスのみ認めているサービス（ただし、ユーザーに無料で提供しているサービスは除く）」「企業、官公庁その他の団体におけるイントラネット内で提供されるサービス」を、ライセンス終了の対象として挙げ、その条件での利用は YOLP Premier を案内している（https://developer.yahoo.co.jp/webapi/map/ ）。**そらばんの第1段階は社員限定の社内利用（spec §13.2）であり、無償の YOLP で使えるかは未確認。LINEヤフー（または販売代理店）への確認が必要** |
| 個人情報 | リクエストに個人情報（座標、住所、検索語など）を含む場合は本人の同意を得ていることを保証する（https://developer.yahoo.co.jp/webapi/map/ ） |
