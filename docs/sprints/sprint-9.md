# Sprint 9: 地図での地点指定の強化（現在地・住所検索・長押し／右クリック）

> 親文書：`docs/spec.md` §13.6（2026-10-19 の差し込み）・§13.8.1 ／ `docs/00_NORTH_STAR.md` §0.1.2・§0.1.7
> 前提：Sprint 8 が完了していること。地番を Neon に置く案（未決 2）を採る場合だけ、Sprint 8 の接続層とマイグレーションを使う。それ以外は Sprint 8 に依存しない。
> ※ Next.js は破壊的変更を含むため、実装前に `node_modules/next/dist/docs/` を参照（`apps/web/AGENTS.md`）。

## 目的と位置付け

点検の現場では、飛行地点を住所で探せない（山林・農地・河川敷・港湾など）か、住所で探せても町字の代表点にしか合わないことが多い。判定の正確さは地点の正確さに依存するため、地点を早く正しく指定できるようにする。North Star §0.1.7 の 1（手間か誤りを減らす）・2（山陰で自社の点検が飛ぶ場所で使う）に当たる。判定ロジックと証跡 ID の計算は変えない（判定の入力は従来どおり緯度経度だけ）。

ユーザー承認済みの内容（spec §13.8.1、2026-10-19 追記）：①ブラウザの位置情報による現在地ボタン、②公的データを基本に Yahoo! JAPAN の住所検索で補う住所検索、③地図の長押し（スマートフォン）・右クリックによる地点指定。Google のジオコーディングは、規約上 Google の地図以外（本アプリは MapLibre）と組み合わせられないため使わない。

## 現状（2026-10-19、`feat/sprint-7-regulations` 時点）

- 住所検索は `apps/web/src/app/api/geocode/route.ts` が国土地理院の住所検索（`https://msearch.gsi.go.jp/address-search/AddressSearch`）を呼び、上位 5 件を返す。結果に精度（どの階層で一致したか）の情報はない。1 件なら即座に移動・判定、複数なら一覧から選ぶ（`regulation-checker.tsx` の `handleGeocode`）。
- 地図（`regulation-map.tsx`）は左クリック・タップで地点を指定する（`map.on("click")`）。長押し・右クリックの扱いはない。現在地の機能はない。
- 地点が決まると `goToLocation` が即座に `/api/check`・`/api/diagnose` を呼ぶ。履歴（`soraban:history:v1`、localStorage）には座標と、国土地理院の逆ジオコーダで得た住所（`resolvedAddress`）が残る。

## 実装する機能

- **A. 公的データによる住所検索（鳥取県・島根県）**
  - A-1（最初に行う計測。結果は `packages/regulations/data/address/README.md` に残す）：アドレス・ベース・レジストリの鳥取県（31）・島根県（32）について、町字・住居表示（街区・住居）・地番の各件数、うち座標を持つ件数、取得ファイルの容量、索引にした後の容量を計測する。地番は市町村ごとの「位置付き件数／全件数」を記録する。取得日とデータの版を記録する。
  - A-2：町字と住居表示（座標付き）を、検索用の静的索引（例：`packages/regulations/data/address/`）にしてリポジトリに同梱し、サーバー側の検索で静的 import する（Sprint 7 の DID と同じ作法。実行時のファイル読み込みに頼らない）。同梱する住所データの合計が 10MB を超える場合は実装を止めてオーケストレーターに報告する。
  - A-3：地番（座標付き）は、A-1 の容量が同梱の上限内なら A-2 と同じく同梱する。超える場合の扱いは未決 2（推奨：Neon の表に入れ、投入はスクリプト。DB 未設定・不達なら地番の検索だけを止め、その旨を結果に表示する）。
  - 取り込みには abr-geocoder の取り込み処理か、データの CSV を直接読む変換スクリプト（例：`scripts/build-address-index.ts`）を使う。どちらにしても、再実行で同じ索引ができ、取得元 URL・取得日・版を索引のメタデータに書く。
  - 照合（例：`packages/geo` か新しい `packages/address` に置く）：都道府県名・郡名の省略、全角・半角、漢数字と算用数字、「丁目」「番地」「番」「号」「-」「の」の表記揺れ、「大字」「字」の有無を吸収する。完全一致の階層の深い順（地番・住居 → 街区 → 町字 → 市町村）に並べる。
  - 実行時に外部 API を呼ばない（公的データの検索は同梱索引か自前の DB だけで完結する）。
- **B. 検索の順序と Yahoo! による補完**
  - `/api/geocode` を次の順に組み直す：①同梱索引（と、未決 2 で Neon を選んだ場合の地番の表）、②国土地理院の住所検索、③Yahoo! ジオコーダ（`YAHOO_APP_ID` が設定されているときだけ）。
  - Yahoo! を呼ぶのは、①②の結果がないとき、または入力に番地・号があるのに①②が町字の代表点までしか一致しないときに限る（推奨。未決 3）。
  - 各結果に、出典（`abr`・`gsi`・`yahoo`）、一致した階層（`parcel`・`residence`・`block`・`machiaza`・`city`・`prefecture`・`unknown`）、表示名、緯度経度を持たせる。画面には出典名と、階層に応じた精度の説明（例：「町字の代表点。実際の飛行地点は地図で指定してください」）を出す。
  - `YAHOO_APP_ID` が未設定なら、Yahoo! へは一切通信せず、①②だけで動く。Yahoo! の応答エラー・タイムアウト（既定 3 秒）でも①②の結果は返す。
  - `YAHOO_APP_ID` はサーバー側の環境変数としてだけ使い、ブラウザに送らない。テスト用に呼び出し先を差し替える環境変数（例：`YAHOO_GEOCODER_ENDPOINT`）を持つ。
  - Yahoo! の応答はキャッシュしない（`fetch` は `cache: "no-store"`。サーバー側の記憶もしない）。国土地理院の結果のキャッシュ（現行 `revalidate: 3600`）は維持してよい。
  - 履歴（localStorage）と DB には、Yahoo! が返した住所文字列を保存しない。地点が決まった後の住所表示は、従来どおり国土地理院の逆ジオコーダの結果（`resolvedAddress`）を使う。保存されるのは利用者が確定した地点の座標だけとし、この扱いが YOLP の保存禁止に当たらないかは LINEヤフーへの確認事項に含める（未決 4）。
  - Yahoo! が有効なとき（`YAHOO_APP_ID` 設定時）だけ、Yahoo! の所定のクレジットを画面下部に表示する。無効なときは表示しない。
  - アドレス・ベース・レジストリと国土地理院の出典を、住所検索の近く（または画面下部のデータ出典欄）に表示する。アドレス・ベース・レジストリは加工して使うため「出典：アドレス・ベース・レジストリ（デジタル庁）を加工して作成」の形にする。データセット台帳（`packages/regulations/data/sources.json`）に、アドレス・ベース・レジストリ、国土地理院の住所検索、Yahoo! ジオコーダを追加する。
- **C. 現在地ボタン**
  - 地図上に「現在地」ボタンを置く。押したときだけ `navigator.geolocation.getCurrentPosition` を 1 回呼ぶ（高精度、タイムアウト 10 秒、キャッシュ不使用）。`watchPosition`（追跡）は使わない。ページを開いただけでは位置を取得しない。
  - 取得できたら、地図をその位置に移し、精度（`coords.accuracy`、メートル）を半径とする円と候補の印を表示し、「現在地（精度 約 N m）」と「この地点で判定」「取消」を示す。**自動では判定しない。**「この地点で判定」を押したときに初めて、通常の地点と同じ流れ（`goToLocation`）で判定する。
  - 精度が 100m を超える場合は「位置の精度が低い。地図で位置を確かめ、長押し（右クリック）で直してください」と表示する。
  - 失敗時の表示：許可されていない（`PERMISSION_DENIED`）→「位置情報の利用が許可されていません。ブラウザの設定で許可するか、住所検索・地図の長押しで指定してください」。取得できない（`POSITION_UNAVAILABLE`）・時間切れ（`TIMEOUT`）→ それぞれの理由と、住所検索・長押しへの案内。どの失敗でも、それまでの地点と判定結果は変えない。自動で再試行しない。
  - 位置情報が使えない環境（`navigator.geolocation` がない、HTTPS でない）では、ボタンを無効にして理由を表示する。
  - 応答ヘッダーで位置情報を自サイトに許可する（`Permissions-Policy: geolocation=(self)`。既存の設定と矛盾しないことを実装時に確認する）。
- **D. 地図の長押し・右クリックによる地点指定**
  - タッチ操作：指 1 本で 500ms 以上押し、その間の移動が 10px 以内なら、その位置を地点に指定する。2 本目の指が触れた・地図が動いた・指が 10px を超えて動いた場合は取り消す。
  - マウス操作：右クリック（MapLibre の `contextmenu`）でその位置を地点に指定し、地図上ではブラウザの右クリックメニューを出さない。
  - 指定後は従来のクリックと同じ流れ（`goToLocation`）で判定する。指定方法（長押し・右クリック・クリック）を短く表示する（例：「地図で指定しました」）。
  - 単タップ（タッチ端末）での地点指定を続けるかは未決 1。
  - 住所検索で町字の代表点しか得られない場合や、地番の位置がない地域では、長押し・右クリックで実際の飛行地点を指定するよう案内する（B の精度の説明と同じ文言を使う）。
- **E. プライバシー**
  - 現在地は端末内（ブラウザ）で地図の表示と候補の印にだけ使う。「この地点で判定」を押すまで、サーバー・外部 API に送らない。端末内にも保存しない（localStorage・Cookie・IndexedDB に現在地や精度を書かない）。
  - 「この地点で判定」を押した後は、他の地点と同じく判定のために座標をサーバーに送り、履歴と（Sprint 8 の）`evidence_log` に残る。その際、「現在地から指定した」こと、精度、取得時刻は送らず、記録しない。
  - 現在地ボタンの近くに「現在地はこの端末の中で地図の表示に使います。『この地点で判定』を押したときだけ、判定のために座標を送ります」と表示する。
  - Yahoo! の補完が有効なとき、入力した住所の文字列が LINEヤフーに送られる旨を住所検索の近くに表示する。
  - 判定の入力と証跡 ID の計算に、住所検索の出典や指定方法を含めない（同じ座標なら、指定方法によらず判定は同じ）。

## 地番しかない地域での限界

- 山陰の農地・山林・河川沿いの多くは住居表示がなく、住所は地番で表される。地番の位置は公共座標系の登記所備付地図がある地域にしかなく、公図（任意座標系）の地域では位置がない。この場合、住所検索は町字の代表点までしか一致せず、代表点は実際の飛行地点から数百 m 以上離れることがある。
- 判定（DID、飛行禁止法の 1,000m、公園・史跡など）は地点の数百 m の違いで結果が変わりうる。代表点での判定を飛行地点の判定として使わないよう、画面で精度を示し、長押し・右クリック（または座標入力）で実際の地点を指定する流れを用意する。これが D の主な目的である。
- Yahoo! の補完でも、地番での一致の範囲は**未確認**。

## 範囲外

- 鳥取県・島根県以外の住所データ
- Google のジオコーディング・地図

## スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。「単体」は `pnpm test`、「E2E」は Playwright（`pnpm test:e2e`）で検証する。現在地は Playwright の `geolocation` と `permissions` の設定で、長押しはタッチを有効にしたコンテキストで CDP（`Input.dispatchTouchEvent`）などを使って再現する。

### A. 公的データ

- [ ] `packages/regulations/data/address/README.md` に、鳥取県・島根県の町字・住居表示・地番の件数、座標付き件数、容量、市町村ごとの地番の位置付き件数、取得元 URL・取得日・版がある。
- [ ] （単体）同梱索引から無作為に抽出した 50 件（町字・住居表示・地番〈同梱した場合〉を含む。抽出の乱数種を固定）を、表記揺れ 4 種（都道府県名の省略、算用数字→漢数字、「番地」→「-」、全角化）に変換して検索すると、元の地点が 1 位に来る割合が 95% 以上。
- [ ] （単体）一致した階層が正しく返る：町字までしか合わない入力は `machiaza`、住居表示の入力は `residence` または `block`、地番の入力は `parcel`（地番を収録した場合）。
- [ ] （単体）公的データの検索処理が外部へ通信しない（`fetch` を失敗させても①の結果が返る）。
- [ ] 住所データの同梱分の合計容量が 10MB 以下（超えた場合は契約前にオーケストレーター経由でユーザーの判断を得ている）。

### B. 検索の順序と Yahoo!

- [ ] （E2E）`YAHOO_APP_ID` 未設定の `next start` で、鳥取県・島根県の住所を検索すると、結果に出典と精度の説明が表示される。Yahoo! のクレジットは表示されず、Yahoo! のエンドポイントへの通信が 1 件もない（Playwright の通信記録とサーバー側の差し替え先のどちらでも確認できる）。
- [ ] （単体）`YAHOO_APP_ID` 設定時：①②の結果がない入力、および番地付きの入力で①②が `machiaza` 止まりの場合だけ Yahoo! を呼び、①②で `parcel`・`residence`・`block` が得られた場合は呼ばない。
- [ ] （単体）Yahoo! がエラー・3 秒超過でも、①②の結果が返り、応答が 4 秒以内に終わる。
- [ ] （単体）Yahoo! の呼び出しに `cache: "no-store"` が付き、同じ入力を 2 回検索すると Yahoo! を 2 回呼ぶ。
- [ ] （E2E）`YAHOO_APP_ID` を設定し呼び出し先を差し替えた起動で、Yahoo! 由来の結果に出典「Yahoo!」が表示され、画面下部に所定のクレジット（API ドキュメントへのリンク）が表示される。
- [ ] （E2E）Yahoo! 由来の結果で地点を決めた後、localStorage の履歴に Yahoo! が返した住所文字列が含まれない。
- [ ] （単体）`/api/geocode` の応答とブラウザに渡す値に `YAHOO_APP_ID` の値が含まれない。
- [ ] （E2E）画面に「アドレス・ベース・レジストリ（デジタル庁）を加工して作成」の出典が表示される。データセット台帳に 3 つの出典があり、各件に URL・ライセンス（または利用条件）・確認日がある。

### C. 現在地

- [ ] （E2E）位置情報を許可し座標を与えたコンテキストで現在地ボタンを押すと、地図がその位置に移り、精度の円と「現在地（精度 約 N m）」が表示される。この時点では `/api/check`・`/api/diagnose`・`/api/geocode` への通信が発生しない。
- [ ] （E2E）続けて「この地点で判定」を押すと、与えた座標（小数 6 桁）で判定が行われ、緯度・経度の入力欄に反映される。
- [ ] （E2E）精度 150m を与えると、精度が低い旨の表示が出る。
- [ ] （E2E）位置情報を許可しないコンテキストで現在地ボタンを押すと、許可されていない旨と住所検索・長押しへの案内が表示され、それまでの地点と判定結果が変わらない。
- [ ] （単体）`POSITION_UNAVAILABLE`・`TIMEOUT` のそれぞれで所定の文言になり、自動で再試行しない。`watchPosition` を呼ばない。
- [ ] （E2E）ページを開いただけでは位置情報を要求しない（ボタンを押す前に `getCurrentPosition` が呼ばれない）。

### D. 長押し・右クリック

- [ ] （E2E）タッチを有効にしたコンテキストで、地図上の一点を 600ms 押すと、その位置が地点になり判定が行われる。300ms で離した場合は長押しとして扱われない。
- [ ] （E2E）押している間に 20px 動かすと地点は変わらない。2 本指で触れた場合も変わらない。
- [ ] （E2E）デスクトップのコンテキストで地図を右クリックすると、その位置が地点になり、ブラウザの右クリックメニューが出ない（`contextmenu` の既定動作が止まっている）。
- [ ] （E2E）町字の代表点に一致した検索結果を選ぶと、「町字の代表点。実際の飛行地点は地図で指定してください」が表示される。

### E. プライバシーと回帰

## ユーザー作業（エージェントは行わない）

1. **Yahoo! のアプリ登録**：会社の Yahoo! JAPAN ID で Yahoo! デベロッパーネットワークにアプリケーションを登録し、Client ID を取得する。
2. **利用条件の確認**：LINEヤフー（または YOLP Premier の販売代理店）に、次を確認する。社員限定の社内向けサービスで無償の YOLP を使えるか（YOLP Premier が必要か）、ジオコーダの結果を MapLibre（Yahoo! 以外の地図）上に表示してよいか、利用者が確定した地点の座標を飛行の記録として保存することが保存・キャッシュの禁止に当たらないか、Vercel（シンガポール）からの呼び出しに制限がないか。
3. **キーの設定**：2 の確認で問題がない場合に限り、Vercel の Production に `YAHOO_APP_ID` を設定して再デプロイする。Preview・Development には設定しない（推奨）。確認が済むまで、住所検索は公的データだけで動く。
4. **地番を Neon に置く場合（未決 2 で採用したとき）**：Sprint 8 と同じ手順で本番にマイグレーションを適用した後、地番の投入スクリプトを手元から本番に対して実行する（手順は generator が `packages/db/README.md` に書く）。

## 未決事項（実装前にユーザーの確認が必要）

1. タッチ端末で単タップによる地点指定を続けるか。推奨：やめて長押しに一本化する（現場で地図を動かそうとして地点が変わる誤操作を防ぐ）。マウスの左クリックは従来どおり指定とする。続ける場合、D は追加の手段になる。
2. 地番データが同梱の上限（住所データ合計 10MB）を超える場合の置き場所。推奨：Neon の表に入れる（Sprint 8 の土台を使う。投入は本番ではユーザー作業。DB 不達時は地番の検索だけを止める）。代替：地番は収録せず、町字・住居表示と長押しで補う。
3. Yahoo! を呼ぶ条件。推奨：公的データの結果がないとき、または番地付きの入力で町字止まりのときだけ（回数の節約と、出典を公的データ中心に保つため）。代替：常に公的データと並べて表示する。
4. Yahoo! の利用条件（ユーザー作業 2）の確認結果。確認が済むまでは `YAHOO_APP_ID` を本番に設定しない。YOLP Premier が必要と分かった場合、契約するか、Yahoo! の補完をやめて公的データと長押しだけにするかを決める。
