### 3.3 ロゴの珊瑚〜赤（`#CA4F48`）と判定の赤・黄の混同を避けるルール（契約）

判定の赤（飛行不可）は塗り `#A81D28`／文字 `#9A1A24`、黄（要手続き）は塗り `#EDB800`（`soraban-tokens.css`【確認】）。ロゴの珊瑚 `#CA4F48` は判定の赤塗りと比 1.64、橙 `#EBA15C` と比 2.07 で、**色だけでは近い**。

| ルール | 内容 |
|---|---|
| R-1 | **ロゴの珊瑚・赤は、ロゴ・ブランド要素（ヘッダーのロゴ、PDF の見出し、アイコン、OGP、空の状態の挿絵）だけに使い、UI の部品（ボタン・札・罫・状態の印・地図のレイヤー・範囲）に使わない**。UI の赤は判定色と、取消・危険の操作の赤だけ |
| R-2 | ロゴを置く場所の近く（**判定の行・結論の札・判定の画面・地図の判定レイヤーから、ロゴの大きさ以上の余白**）に置かない。判定の画面と通報の主画面の本文領域にはロゴを置かない（ヘッダーの小さなロゴだけ） |
| R-3 | 判定の赤・黄は、色に加えて**形と言葉**を必ず併用（既存。×・△・丸にチェック・輪・点線の？）。ロゴの珊瑚には、判定の形（×など）を使わない |
| R-4 | ロゴの色は、PDF・アイコンで**単色の墨や白抜きの版**も用意し、判定の PDF（判定の結果を載せる PDF）の見出しでは、ロゴを墨の単色にして判定の赤と並べない |
| R-5 | 色覚の模擬（Sprint 16 の S-3: 色なし・赤緑の色覚）で、ロゴ（珊瑚）と判定の赤が**形・位置・言葉**で区別できること（ロゴは常にヘッダー・見出しの固定の位置、判定は結果の領域） |
| R-6 | ロゴの使用ルール（余白・最小サイズ・色違いの可否・文字付きロゴの有無）は**未確認**（ユーザーに確認）。確認までは、ロゴ画像の色・形を変えない（拡大縮小と余白のみ） |
| R-7 | 橙のあしらいは、判定の黄から離す（上の使い分けの面積・位置のルール）。橙と黄の区別は色覚の模擬で確かめる |

## 4. ブランド要素（たたき台）

オレンジを軸に、**品のある統一**: 白〜ごく薄いグレーの地、墨の文字、橙は随所に**小さく・効かせて**使う。

| 要素 | 方向（案） |
|---|---|
| ロゴ | 「そらばん」のワードマーク（書体は 1 つ決める）＋提供元の併記（「フューチャーテック株式会社」。商標・ロゴの扱いは `legal-info-plan.md` U6・Q-L9）。そらばんのシンボルが要るか（要らない案もある） |
| ヘッダー | 公開の `/`: 小さなシンボル＋ワードマーク、橙の細い線。運航管理: 左メニューの上のワードマーク、現場では最小（装飾なし） |
| フッター | 提供元・規約・免責・問い合わせ（`legal-info-plan.md`）。橙の細い区切り線 |
| 空の状態 | 小さな線画（SVG）1 点と 1〜2 行の説明、次の操作のボタン。橙の差し色は 1 点 |
| 読み込み | 橙の細い進行線または点（動きは Sprint 16 の動きの規則: 2 種類まで、現場は 0） |
| PDF の見出し | 提供元・出力日・橙の細線。印刷の白黒でも読める |
| PWA のアイコン | 橙の面に白または墨のシンボル（公式の色が決まってから）。スプラッシュは白地に中央のシンボル |
| OGP | 白地＋ワードマーク＋橙の線 |
| 挿絵（`/` のトップ） | 線画（墨）＋日の出の橙。大きな絵は Firefly、細かい図（アイコン・空の状態）は SVG |

### 4.1 画像の作り方の方針

`docs/HANDOFF.md`（11b: 「見出しの線画は、ユーザーが Adobe Firefly で生成した PNG に差し替え」）と Sprint 12g（「アイコン・コマンドパレット・シート・ポップオーバーは自作」。依存を増やさない）に従う: **アイコン・小さな図は SVG（自作。インライン）／大きな絵（トップの挿絵、OGP の絵）だけ Firefly（ユーザーが生成し、PNG を渡す。生成した画像の権利・利用条件は Adobe の規約を確認※要再確認）**。画像の容量は LCP の要素にしない（既存の方針: インライン SVG は画像要求 0 件）。他社の絵・ロゴの写しをしない。

## 6. 順序

`ops-completion-plan.md` §6・§16: 第一段階（山陰で通報・日誌・点検が完結）が先。Sprint 16（白基調。16-1 トークン、16-2 現場、16-3 後始末）は、品質基準の中核として前・中・後に置く。**ブランドビジュアル（本企画）は、16-1 のトークンが固まり、公式のオレンジの値が決まってから**（16-3 の前後）。ユーザーが企画し直す作業（方向の選定・Firefly の生成）は、第一段階の開発と**並行して進められるユーザー作業**。

## 7. ユーザーに聞くこと

1. **公式の色コード**（HEX など）、または公式のロゴデータ（SVG）・ブランドガイド。ロゴの測定値（`#EBA15C` ほか。公式値ではない）を出発点にしてよいか。ロゴの使用ルール（余白・最小サイズ・色違いの可否・文字付きロゴの有無）。
2. 「衣装イラスト」＝「意匠イラスト（装飾的なイラスト）」でよいか。
3. そらばんのシンボルを新しく作るか、既存のフューチャーテックのロゴ（提供済み）を併記するか（商標の扱い）。
4. Firefly を使うか（使うなら生成はユーザー）。

- 色覚・日差しでの橙と判定の黄の区別（見本と実機で確かめる）。
