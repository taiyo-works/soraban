## 0. 要点

- soraban に書き出しのルートは無い【確認】。43-1 で様式 1（飛行記録）・様式 2（日常点検）の CSV と、組織のデータの控えの JSON を、43-2 で計画の範囲・離着陸地点の KML の書き出しと読み込みを作る。
- **SQLite の書き出しは作らない**（ユーザーの決定）。**様式 3 は作らない**（記録の場所が無い）。
- 書き出したファイルは利用者の端末に保存される。これは利用者の明示の操作による保存で、アプリが端末の保存領域（localStorage・IndexedDB・Cache）に残すものではない。画面にその旨を書く。
- 書き出しは監査の記録を残す（誰が・いつ・何を）。記録の作法は既存の証跡の作法に合わせる（`evidence_log` の形は変えない。別の追記専用の記録を使うか、既存の監査の仕組みに乗せるかは generator が提案し reviewer が確かめる）。

## 1. 実装する機能

### 43-1

- **機能A: 様式 1・2 の CSV** — 日誌の画面から、期間（開始日・終了日）と機体で絞って書き出す。列は様式の項目の順（Sprint 11 の項目）。取消の版は出さない（最新の有効な版だけ）。文字コードは UTF-8（BOM つき。表計算ソフトでの文字化けを避ける）。確定の状態が無いため、ファイル名と 1 行目に「確定前の記録」を明記する（日誌の確定は仮 23 の範囲。Q2）。
- **機能B: 組織のデータの控え（JSON）** — 運航管理者だけ。計画・飛行記録・点検・機体・操縦者・許可・承認・事故の最新の版と、版の履歴のハッシュチェーンの先頭・末尾のハッシュを含む。技能証明書の番号を含めるかは Q（§6）。
- **機能C: 大きな出力** — 件数が多いときに分割して送る（メモリに全件を載せない）。

### 43-2

- **機能D: KML の書き出し** — 計画の範囲（多角形・円は多角形に近似したもの＋中心）と離着陸地点（あれば）を KML で書き出す。範囲の無い計画は点だけ。
- **機能E: KML の読み込み** — 計画の作成・訂正で KML を選ぶと、最初の多角形を範囲として読み、地図で確かめてから保存する。上限（大きさ・頂点の数）は 19-1a の範囲の上限と同じ定数を使う。読んだ範囲は 19-1a の検査（自己交差・座標の順・上限）を通す。読み込みはブラウザの中で行い、ファイルの中身を端末の保存領域に残さない。

## 2. スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

### 43-1

- [ ] **K1-1（CSV）** 期間と機体で絞った様式 1・2 の CSV が書き出せ、列の順と見出しが様式の項目と一致し、取消の版が含まれない。1 行目またはファイル名に「確定前の記録」がある。［DB テスト＋E2E-DB のダウンロード］
- [ ] **K1-2（CSV の安全）** セルが `=`・`+`・`-`・`@` で始まる値は、表計算ソフトの式として解釈されない形にする（先頭に `'` を付けるなど）。改行・カンマ・ダブルクォートを含む値が崩れない。［単体］
- [ ] **K1-3（JSON）** 運航管理者だけが書き出せ、他の役割は 403。他の組織のデータが含まれない。版の履歴の先頭・末尾のハッシュが含まれ、`verify_record_chain` の結果と一致する。［DB テスト］
- [ ] **K1-4（監査）** 書き出しのたびに、誰が・いつ・何を（種類・期間・件数）書き出したかが追記専用で記録される。記録に CSV の中身は含めない。［DB テスト］
- [ ] **K1-5（大きな出力）** 5,000 件の飛行記録のシードで、書き出しが完了し、サーバーのメモリに全件を一度に載せない（分割の読み出しを単体で確かめる）。［単体＋DB テスト］
- [ ] **K1-6（フラグ）** `OPS_ENABLED` が無効のとき、書き出しの API は 404。［E2E］

### 43-2

- [ ] **K2-1（書き出し）** 多角形・円・点だけの計画のそれぞれで KML が書き出せ、読み戻すと頂点・中心が丸め（小数 6 桁）以内で一致する。座標の順（経度, 緯度）を取り違えない。［単体］
- [ ] **K2-2（読み込み）** KML の最初の多角形が範囲として地図に出て、保存すると 19-1b の API で範囲が保存される。自己交差・上限超え・座標の順の誤り・多角形の無いファイル・壊れたファイルは、それぞれの理由の文で拒否し、何も保存しない。［単体＋E2E-DB］
- [ ] **K2-3（安全な読み込み）** 外部の実体の参照（XML の外部実体・外部のリンク）を読まない。上限を超える大きさのファイルは読まずに拒否する。［単体］
- [ ] **K2-4（端末）** 読み込んだファイルの中身・座標が localStorage・IndexedDB に残らない（走査で 0 件）。［E2E-DB］
- [ ] **K-回帰** 両 PR とも、`data-testid` の基準の差分 0、既存のテストがすべて通る。

## 4. 触る範囲

`app/api/ops/`（書き出しのルートの新規）、`server/ops/`（抽出の関数）、`packages/geo`（KML の変換。依存を足さずに書けるかを generator が判断）、日誌の画面、計画の画面・作成の画面。マイグレーションは監査の記録の置き場所しだい（既存の仕組みに乗れば不要）。

## 5. やらないこと

- SQLite の書き出し、様式 3、PDF（仮 23）、日誌の確定。
- 読み込みでの複数の範囲（19-2d の後に検討）。
- 他のアプリの独自の形式（GeoJSON の読み込みは KML と同じ検査で足せるが、今回は KML だけ）。

## 6. 質問（この Sprint 内で決める）

## 7. 安全側の考え方

- 読み込みは保存の前に地図と頂点の数で確かめさせ、黙って保存しない。
