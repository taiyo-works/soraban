## 1. 飛行計画通報のメインメニュー（PDF）

区分は 2 つ。

1. **飛行計画の登録に必要な情報を準備する**
   - 無人航空機情報の登録・変更（飛行を行う機体を登録する。**飛行計画の登録の前に必要**）
   - 操縦者情報の登録・変更（同上）
   - どちらも「飛行許可・承認申請時に登録を行った場合、再度の登録は不要」と書かれている（許可・承認申請のページを別タブで開く導線がある）。
2. **飛行計画を登録・参照する**
   - 飛行計画の登録（登録済みの飛行計画の管理を含む）
   - 飛行計画の参照（**他の無人航空機運航者の飛行計画**の参照）

その他: 個人情報保護、利用規約、動作環境、アクセシビリティ、関連リンク、「Copyright© MLIT Japan」。

## 2. 飛行計画一覧

- 絞り込み: 飛行ステータス（計画・飛行中・飛行終了）と、飛行計画の重複（重複なし・調整要・調整済み）。
- 説明文（要旨）:
  - 飛行計画の重複に関する調整内容は、**飛行終了日から 30 日後に削除**される。
  - **認定 USP のシステムから登録された飛行計画は、DIPS 2.0 上で編集できない**。登録に利用した認定 USP のシステムから編集する。
- 表の列: 飛行計画名称、飛行計画 ID、飛行開始日時-終了日時、飛行計画の重複。
- ボタン: 全チェック、全クリア、一括削除、**新規通報**、戻る。

## 4. この記録から分かること（アプリの設計への影響。※要再確認を含む）

1. **DIPS の通報は、事前に DIPS へ登録した機体・操縦者の情報を使う。** アプリが機体登録・操縦者登録を代行することは、サービスの境界（申請はしない）の外。利用者が DIPS で登録済みであることが前提になる（アプリの機体・操縦者の台帳との対応のとり方を設計する）。
2. **「認定 USP」という区分が DIPS にある。** 認定 USP のシステムから登録した飛行計画は DIPS 上で編集できない、と書かれている。**このアプリが API で通報を送る場合の位置づけ（認定 USP に当たるか、必要な認定や手続きがあるか）は、一次資料と専門家で確認が必要**（※要再確認。推測しない）。
3. 通報フォームには**立入管理措置、補助者人数、係留飛行、出発地・目的地、最大飛行時間と所要時間、飛行速度、飛行高度、連絡先**など、アプリの現在の計画の項目にない（または粒度が違う）ものがある。アプリの通報画面の項目は、この構成に合わせて網羅する必要がある。
4. 「飛行計画の参照」（他の運航者の計画）と、一覧の「飛行計画の重複」「調整要・調整済み」は、**重複の表示と調整**に関係する。API で取得できるかは要確認。
5. 開始日時から終了日時が決まる、飛行計画名称の既定が時刻入りなど、**DIPS の入力の仕様に合わせたバリデーション**が要る。

## 5. 確認できていないこと（次の撮影・資料で埋める）

- 立入管理措置の続きの項目。
- 地図で飛行範囲を描く操作（点・線・円・多角形）と、そのとき DIPS が持つ入力（座標、半径、高度の上限など）。
- 「定期・複数日指定」を押したときの画面。
- 登録後の確認画面、受付番号（飛行計画 ID）の表示、更新・取消の操作。
