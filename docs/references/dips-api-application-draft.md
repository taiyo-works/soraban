## 固定 IP について（2026-10-21 時点：未定）
- 会社の回線が固定 IP か不明。確認できるまで、3-2 は空欄のままにせず、申請を保留する。
- 提案：検証・本番とも、国内の VPS（固定 IPv4 付き）に中継を置く。会社の回線の契約や停電に左右されず、同じ IP を本番の申請にも使える（本番は「同上」と書ける）。
- 会社の回線が固定 IP なら、検証だけ会社の回線で行うこともできる。

## 利用範囲について（2026-10-21 更新：当面は社内のみ）
- 当面は社内の利用だけ。航空局への「複数の事業者への提供の可否」の確認は、外部へ提供する段階まで保留する（申請の前提にしない）。
- 2-13 の用途は、検証環境の申請で「開発用」、本番環境の申請で「商用サービス用」か、社内の業務用として該当する方を選ぶ（本番の申請の前に再確認）。
- 将来、外部へ提供することになれば、変更申請（設定通知書を用いた変更）と、利用規約上の確認が必要。

## 申請前に航空局へ確認したいこと（申請窓口 hqt-jcab.mujin@ki.mlit.go.jp）
1. SaaS として複数の事業者に提供し、各事業者が自分の DIPS2.0 アカウントでログインして通報する使い方は、利用規約上、認められるか。
2. アクセス元 IP の制限は、どの通信に掛かるか（トークン交換、API 呼び出し、両方）。
3. 通報の取消・削除の API はあるか（ガイドラインに記載なし）。
4. トークンの有効時間（サンプル値 300 秒・3600 秒）は変更できるか。PKCE は使えるか。
5. 利用料、レート制限、障害時の連絡。
6. クライアント ID は FPR と FPA で共通か。リダイレクト URL は複数登録できるか。
