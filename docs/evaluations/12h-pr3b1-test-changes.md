## E. 点検の一覧の区分チップ（`<a>` か `Link` か）の調査

③a で、区分チップを `Link` から通常の `<a>` に変えた（`?timing=` の切り替えが画面に反映されないことがあった。原因は未特定）。③b1 で調べた。

- **ドキュメント**（`node_modules/next/dist/docs/01-app/02-guides/preserving-ui-state.md`、`01-getting-started/04-linking-and-navigating.md`）：このアプリは `cacheComponents: true`。Cache Components では、画面を離れると React の `<Activity>` で隠して（DOM と状態を残して）最大 3 つの経路を保つ。動的な経路の先読み（prefetch）は、`loading.tsx` がなければ省かれる。
- **仮説 1（先読みの結果が古い）**：チップを `prefetch={false}` にして試した。**直らなかった**。
- **再現**：本番ビルド（`next start`）で、`/ops/inspections` → 「飛行後」→（点検を 1 件記録）→「すべて」の往復を繰り返すと、**4 往復目に「すべて」を押しても URL と画面が変わらない**ことを再現した（`P3b1-7` の最初の版が失敗。別の手元の再現スクリプトでも 6 往復中 4 往復目）。このとき通信の記録では、`?_rsc=…` の取得は **200 で返っている**（サーバーは応答している）のに、画面が切り替わらず、URL も更新されない。データが少ない手元（記録 2 件）では再現しないことがあり、**記録が多いとき（未実施 18 件・記録が数十件）に起きた**。
- **結論**：原因は **Next.js 16.2.4 のクライアント遷移（Activity で隠した前の画面の復元）側にあると見られる**が、**アプリ側では直せなかった**（`prefetch={false}` では不足）。**通常の `<a>`（画面ごと読み直す）に統一する**。同じ作り（同じ画面の中で `?query` だけを切り替える）の次の 5 か所も `<a>` にした：点検のチップ、日誌のタブ（`?tab=`）、計画の「これから／過去／中止」（`?view=`）と 2 つの絞り込み（`?attention=`・`?state=`）、一覧の「取消済みも含める」の切り替え（`VoidedToggle`）。別の画面へ行くリンクは `Link` のまま。
- **検査**：`P3b1-7`（点検のチップを 6 往復。間に点検を 1 件記録して、「すべて」へ戻ると件数が増えている）。`<a>` では 109 件の通しの実行で安定して通った。
- **残る懸念**：`Link` の同じ現象が、別の画面で起きる可能性はある（本番の画面では、同じ画面内の `?query` 切り替えに `Link` を使う箇所を、③b1 の範囲では残していない。③b2 の範囲に残りがないか grep で確かめる）。

## F. 契約と食い違った判断

1. **`.ds` 全体ではなく `.ds.ops-v2` の中だけを v2 にした**（契約 §6.2 は `globals.css` の `--r-journal`・`--radius-ctl`・`--radius-sharp` を付け替える）。理由：`/ops/design`（旧い見本）が `.ds` を使い、見本の検査（T-12）がある。④で見本を消すとき、`ops-v2.css` の「旧い名前の置き換え」を `globals.css` に畳む。`/` の CSS は増えない（Q-18a：`/` の CSS −195B）。
2. **点検の入力ボタンなどの寸法**：普通のボタンは 48px、主ボタンは 56px（契約どおり）。日誌・ホームの「記録を入力」は、既存の検査（56px 以上）を守るため、スマホで 56px にした。
