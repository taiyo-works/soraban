## 3. I-3 の詳細（不合格の根拠）

条件: 日誌から `?takeoffAt=2027-01-05T11:00` で移り、実施時刻 11:30（離陸より後）。ブラウザの時計は固定。

**修正の指示（差し戻し先: designer。スタイルと配置だけで直せる。文言は変えない）**

1. 日誌から移ったとき（`dateFirst`）だけ、注記より上の縦を 30px 以上詰める（余裕を見て 36px 以上。目標は注記の下端 ≤ 720）。候補（効果が大きい順）:
   - 画面の副題「飛行の前（または後）に行った日常点検の結果を入力します。」（2 行、約 44px）と、その下の説明「点検は利用者の確認の記録です。…」（2 行、約 52px）の間と周囲を詰める。または日誌から移ったときだけ、副題を 1 行にする、説明を群の補足の位置へ移す。
   - 実施時刻の見出し行（「実施時刻」＋必須）と「今」ボタン（56px）と日付・時刻の行、補足「日本時間（24 時間制、分まで）。…」（2 行、約 34px）の間隔を詰める。補足を注記の後ろへ移すのも可（注記は「実施日時の欄のすぐ下」の趣旨が保たれる範囲で）。
   - 注記の内側の余白を詰める（高さ 159px、見出し行「確認してください」＋記号＋本文 5 行）。
2. 検査も直す（generator か designer。同じ差し戻しの中で）。`sprint16-i-db` の I-3 は `n.y + n.height <= 812` を、`ops-bottom-nav` の上端以下（`navTop`）に変える。ナビの上端は `page.getByTestId("ops-bottom-nav").boundingBox()` で取れる。390×844 も足すとよい。

## 4. 手動シナリオの結果と判断

- **未実施の調子（N-7）**: designer は状態ラベルの調子（情報）を変えず、区画の説明「今日の計画で、飛行前の点検の記録がまだないものです。」で理由を書いた。**妥当**とする。理由は 3 つ。(1) 今日の計画に点検がまだ無いのは、離陸前なら通常の状態で、危険・注意を示すと異常と取り違える。(2) 「今日」の注意色の札が同じカードに並び、緊急度は別の部品で伝わる。(3) 「問題なし」と読める語は使っていない。残る課題は 16-J 以降に送る（申し送り 2）。
- **色なしの模擬**（`s7-gray-*.png`）: 正常＝「済」＋✓の丸、異常＝「異常」＋✕の丸（行に面と左の線）、未記入＝「未記入」＋破線の札。一覧は、点検済み＝✓＋言葉、異常あり＝✕＋言葉、取消済み＝○＋言葉＋破線の枠＋取消線、未実施＝○＋言葉。形と言葉だけで見分けられる。「未実施」と「取消済み」は記号が同じ○だが、言葉と枠で区別できる。
- **文字 200%・360 幅**: `/ops/inspections/new`（新規、保存を押した状態、9 項目すべて異常＋長い備考）と `/ops/inspections` で文書の幅 360/360（横スクロール 0）。390 幅も 0。「異常」の行は、結果の選択が `auto-fit` で折り返し、切れない。
- **読み上げの属性**: 群の見出しは `aria-hidden` の「2/3」＋ `sr-only`「完了 n/3 項目」。進み具合の `inspection-progress` は `aria-live` を持たない（N-3）。`aria-live` を持つのは `inspection-missing-count` と、`SaveRow` にもとからある「送信しています…」用の空の span の 2 つで、後者は変更前から全フォーム共通。重複した読み上げはない。依頼の「1 つだけ」は、`inspection-missing-count` が新しく足した唯一のもの、の意味なら ✅。
- **端末に残すもの**: 下書きは `soraban:ops-draft:inspection:<memberId>` と `soraban:ops-current-member` の 2 キーだけ。値の項目は `clientRequestId, aircraftId, pilotId, date, time, timing, placeName, pos, items, specialNotes`（`drafts.ts` と状態の型に差分なし。基準と同じ）。`showMissing`・群の開閉は保存されない。`sessionStorage`・Cache は空。
- **禁止語**: 差分の `apps/web/src`・`e2e` に「完璧・保証・必ず・代行・代理・申請・通報不要・問題なし」の追加 0。§5.4 の追記は、禁止語を使わないという宣言の 1 文にだけ含まれる。画面（入力・保存を押した後・一覧・取消含む・日誌から移った後）の本文・`sr-only`・`aria-label` の走査も 0 件。
- **事実の主張**: 追加なし。群の名前は様式2 の区分でないことを画面で明示している。

## 7. 申し送り（16-J 以降）

1. 320 幅・文字 200% の点検の入力（E-3）。「区分」のラジオの行を折り返すか、列を縦に積む。16-J の日誌の入力にも同じ「区分」の部品がないか確認する。
2. 未実施の点検に時間の経過を反映するか。計画の開始時刻を過ぎて点検がないとき、「未実施」を情報のままにするか、注意に上げるかは、運用の取り決め（`lib/inspection-pending.ts` のコメント）が決まってから。今は情報のままで妥当。
3. 検査の書き方: 「最初の画面に入る」は、画面の高さではなく、固定の下部ナビの上端で測る。16-J 以降の同種の検査にも適用する。
4. 既知の不安定なテストの観測を runbook に追記する案: `sprint9` 306 は HEAD 単独 ×10 で 9 失敗、基準 ×4 で 2 失敗（今回）。`sprint12h-pr2` B1 の「1 フレームで確定」は全体実行で 1 回だけ 895 > 2。単独 ×6 では通過。
5. 触覚（I-6）は未実装のまま。必要なら 16-N までに別途。
