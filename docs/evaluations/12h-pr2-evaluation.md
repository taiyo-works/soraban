### B-3 見つけた問題（画面）

1. **判定を押しても結果が画面に入らない（スマホ）**。375×812 で住所を入れて「この地点を判定する」、または「現在地で判定」を押したあと、`scrollY` は 0 のまま、結論カードの上端は画面の上から **約 1,690px 下**（画面 2 つ分）。ボタンの近くに「判定中」「完了」の表示が見えない（結果は地図・凡例・層の下）。利用者は押したあと何も起きないように見え、2 回スクロールして初めて結論に着く。契約 Q-12「結論は 1 回のスクロール（1 画面分以内）で見える」は **未達**（結論の上端：初期 1,641px／判定直後 1,638〜1,712px。1 画面分のスクロールで見えるのは 1,624px まで）。契約 §6.2 の順（入力 → **結論** → 地図と層）に対し、実装は 入力 → 地図と層（約 680px）→ 結論 で、結論が地図の下。
2. **PC（1280×800）の最初の画面に「現在地で判定」が入らない**。挿絵＋概要で 484px、入力カードの「この地点を判定する」が下端で切れる。契約の条件は 375×812 だけなので契約違反ではないが、「2 つのピルが最初の画面に入る」が PC では成り立たない。
3. **結論カードに「確認日」「出典つき」の札がない**（見本・契約 §6.3「結論の下に『確認日』『出典つき』の札、『結果を PDF で保存』」）。コードのコメントには書いてあるが、実際の表示は「PDF 出力」だけ。見本の注記「ご本人が自分で手続きを済ませた記録の表示です。そらばんが手続きを行ったわけではありません。」「ご本人の名義で作成し、ご本人が提出します。そらばんは入力項目の下書きまでを手伝います。」も画面にない（main にもなかった。契約 §6.3 は「維持」と書くが元が無い）。
4. 地図は 375px で高さ約 198px（層の一覧を含む塊で 684px）。契約に高さの下限はないが、地図を見て操作するには小さい。
