- 契約は「ページ全体の高さ」の上限を置いていない。関係するのは Q-12（結論は 1 回のスクロールで見える）と Q-20（台本ごとの押す回数と、ページのスクロール量が 2 画面分以内）。

- Q-12：未達（§B-3 の 1）。

### C-4 妥当性の評価

- **結論までの経路は main より良い**（4,000 → 1,619px）が、**判定ボタンを押しても自動で結論に移らない**ため、押した人は結論が見えない（約 1,700px 下）。のりさんの要望の核心「目的の情報にたどり着く」を満たしていない。
- 結論の下に、規制ごとのカード（4,700px）と申請支援（5,900px）が続き、目的が「手続きを知りたい」「申請の準備をしたい」の人には、さらに 2〜5 画面分のスクロールが要る。「手続き」は結論の直後（約 360〜2,100px）にあり、ここは良い。
- 「申請支援」「チェックリスト」「書類の下書き」は、結果が出た人の全員に必要なものではない。折りたたみ（既定は閉）にすれば約 5,900px → 約 300px になる。

### C-5 短くする案（3 つ）

1. **判定後に結論へ自動で移動する／結論を入力の直下に置く**（generator）。判定が終わったら結論カードの見出しへスクロールし（`prefers-reduced-motion` ではジャンプ）、フォーカスを移す。契約 §6.2 の順（入力 → 結論 → 地図）に直すなら、地図ブロックを結論の下へ。効果：結論に着くまでのスクロール 約 1,700px → 0。
2. **規制ごとのカードを要約＋展開に**（designer／generator）。既定は「名称・段・1 行の理由」だけで、使用データ・版・改正・出典・確からしさは「根拠を見る」で開く（一覧の「手続きが要る」を先頭に並べる）。効果：4,702px → 約 1,500px（8 件×約 190px）。
3. **申請支援・チェックリスト・書類の下書き・独自マニュアル、「02 収録している規制とデータ」を、1 つずつ閉じた `details` にする**（designer）。効果：約 5,900px＋約 1,300px → 約 600px。合わせて、全体は約 20,200px → 約 9,500px（半分以下）。
