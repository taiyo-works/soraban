## 見つけた不具合と再現手順

### BUG-1（必須・generator）: 着陸後に日誌入力を開くと、飛行前の点検が入らない（12c 回帰）

- 再現: 新しい DB で `pnpm test:e2e:ops -g "12\. 日誌：着陸後"`（基準では通る）。または、飛行前の日常点検を記録 → 離陸 → 着陸 → 「日誌を記入する」を開くと、`inspection-select` が空。
- 原因: `apps/web/src/app/ops/flights/new/page.tsx` 60 行目が `view.items` の `inspection` の点検 ID を使う。S14 で `fieldState` の `checks.inspection` が「いまのラウンド」だけを数える（`field-logic.ts` の `pre` の絞り込み `x.inspectedAt >= roundStartAt`）ため、着陸でラウンドが閉じると、日誌の対象の飛行の点検が消える。
- 副次: 着陸の直後に、今日の次にやること（`today-logic.ts` の `do_inspection`）に「飛行前の日常点検の記録がありません」が出る可能性がある。次のラウンドの意図なら許容だが、日誌待ちの飛行がある間は紛らわしい。要判断。
- 修正指示: 日誌の入力で使う点検は、`takeoffEventId` で指す飛行のラウンド（その離陸より前、前の着陸より後の飛行前点検の最新）から取る。`fieldState` に、各飛行（`flights[i]`）に使われた飛行前点検の ID を持たせ、`flights/new` はそれを使う。12c の E2E を変えずに通すこと。

### BUG-2（必須・generator）: 新規 E2E が、固定のサーバー時計の「未来」の点検を作る

- `sprint14-db.spec.ts` 204・218 行目の `createInspection(..., T12:03 / T12:04)` が、サーバー時計（`OPS_TEST_NOW` = 12:00）より後で `400 in_future`。かつ、飛行後点検は着陸時刻（12:02:05）より後でないと「済」と数えないため、時刻をただ前へずらしても通らない。
- 修正指示: ブラウザの時計・離陸・着陸・点検の時刻をすべてサーバー時計（12:00）以前に収める（例: 11:57:10 に開く、着陸 11:58:05、飛行後点検 11:59、次ラウンドの飛行前点検 11:59。離陸・着陸は ±5 分のずれ内）。私の一時コピーでは、`12:00:10→11:57:10`、`12:02:05→11:58:05`、`12:05:10→11:59:10`、`12:07:10→11:59:40`、点検の時刻 `T11:59` で 6 件すべて通った。

### BUG-3（必須・generator）: 「今日の次にやること」の検査が不成立

- `sprint14-db.spec.ts` 201 行目は `/api/ops/today` の上位 8 件に `do_post_inspection` が含まれることを要求するが、シード済みの組織では tier 1・2 の項目（`confirm_incident_report` ×3、`report` ×5 ほか）で 8 件が埋まり、tier 3 の本項目は出ない（`write_journal` も同様）。新しい DB でも再現。
- 修正指示: 上位 8 件に頼らず検査する。例: 他組織・他の操縦者でなく、`/api/ops/today` に `limit` を渡せるなら渡す、または計画の画面の導出（`field` API の `postPendingCount`）で確かめ、今日の一覧は純粋関数の単体で固定する。または、候補の重みを変えるなら理由を契約に書く（D-7 の「今日の次にやることに出る」は、優先順位の低い tier 3 のため、忙しい組織では見えない。要判断）。

### BUG-4（修正推奨・generator）: D-2 の戻り先が許可・通報で欠ける

- 再現: 現場画面で「許可承認書の登録を開く」→ `/ops/permits?returnTo=…`（一覧）に「現場モードへ戻る」なし。「飛行計画の通報の登録を開く」→ `/ops/plans/:id/report`（`returnTo` なし）に現場へ戻る導線なし。
- 修正指示: 許可の一覧・詳細（登録がある場合は詳細）と通報の画面で `returnTo` を扱う（機体・操縦者の詳細の `safeReturnTo` と同じ作り）。E2E に許可・技能証明・通報の戻りを加える。
- BUG-4b（D-5）: 緊急用務空域の確認に、公表ページへのリンク（`EMERGENCY_SOURCE_OPTIONS` の `url`）を `<a target="_blank" rel="noopener noreferrer">` で出す。確認元・確認日の注記はすでにある。

### BUG-5（任意・generator）: 新規 E2E の最初のテストが時々落ちる

- サーバー起動直後の「現場モードへ戻る」を押したあと、30 秒間 URL が変わらないことがある（5 回中 2 回）。単独・連続で再現しにくい。`click` のあとに `waitForURL` を使う、または戻るリンクの `href` を検査してから遷移する形にして安定させる。

### BUG-6（任意・generator）: 検査の抜け

- D-4（登録の変更 → 満たさない、`gaps` 不変）、離陸・着陸のオフライン（D-11）、D-2 の許可・通報、暗い配色のコントラストの E2E が無い。契約の「核」ではないが、契約の文言にある。仕様ファイル冒頭の「書いた時点では実行していない」の注記は、実行して通した後に更新すること。
