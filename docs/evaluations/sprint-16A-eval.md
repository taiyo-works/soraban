- 測定: `sprint-16A-reeval-15-A7-transition-probe.mjs`（フレームごとに計算色を採取、12 回）。**落ち着いた状態は常に `rgb(31,95,224)` の面＋白文字で 5.57:1**。遷移中の最小は 1.06〜1.35:1（面が地に近い）、途中の値は 2.2・3.1・4.0 …と連続的に上がる（失敗ログの 4.02 も 1.13 も、同じ遷移上の別の瞬間）。`getAnimations()` が 1 件ある間だけ起きる。
- テストは `hero-art` が見えた直後に測るので、初回の判定の完了と重なると遷移中の値を拾う。25 回中 11 回（44%）。前回の全体実行で通ったのは偶然。designer の「単独では成功」もこの確率による。
- 7bcd84d の退行か: **違う**。`git diff 3346eb2 7bcd84d -- apps e2e packages` は、境界線の色のクラス 3 か所とコメントだけ（9 行ずつ）で、背景・遷移・ボタンには触れていない。テスト自体が 16-A の新規（956123c に無い）ので、基準との比較は成り立たない。3346eb2 のビルドでの再現は行っていない（差分が上記だけのため、静的に判断）。
- 利用者への影響: 判定が終わった直後の 180ms の遷移で、実質ない（ホバー等と同じ性質）。K-3 の趣旨（落ち着いた状態の比）は満たす（5.57:1）。

**直し方（アプリは直さない。テスト、generator 宛て・小さい）**: `e2e/field-checks.ts` の `collectTextSamples` の呼び出し前（`sprint16-a.spec.ts` の K-3 の `goto` 後）に、遷移が終わるのを待つ。例: `await page.waitForFunction(() => document.getAnimations().length === 0)`（`/` では初回の判定の完了＝ボタンが有効になり、遷移が止まるまで）。ほかの画面の K-3 や 16-B 以降の測定にも同じ待ちを入れる（`expectContrast` の共通部にするとよい）。直したら `--repeat-each=25` で 25/25 を確かめる。
