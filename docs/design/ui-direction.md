# 画面デザインの方針（Sprint 12g。2026-10-22 作成、2026-10-24 改訂：「航空日誌の紙面」）

そらばんの画面（`/` と `/ops` 以下）を、「LP ぽい」紙面調から、**紙色の地・墨色の文字・藍 1 色の、静かで高機能なプロ向けの業務アプリ**へ刷新するための方針。実装の段階と完了条件は `docs/sprints/sprint-12g.md`。この文書は、デザインシステム（色・文字・形・動き・部品）と情報設計の「正」で、designer・generator・evaluator が参照する。2026-10-24 に、色と形の方針を Apple 系から「航空日誌の紙面」へ改めた（下の決定表）。

## 1. 現状の診断：何が「LP ぽい」のか

12e の画面（375・1280 の明暗の撮影）と、現在のコード（`apps/web/src/app/**`、`components/**`）を読んで確かめた。共通する原因は 5 つ。

1. **説明が先で、操作が後**。見出しのすぐ下に、左線の札（固定の注意書きや画面の説明）が何枚も並び、入力・一覧が画面の下に押される。
2. **紙面調の意匠が「冊子・LP」を連想させる**。方眼の背景、明朝調の細い大きな見出し（Fraunces、`font-light` の 28〜48px）、大文字に字間を空けた小見出し（`eyebrow`）、左に太い線を引いた札（`border-l-2`）、1px の罫線と 2px の角、点線の囲み、影なし。**階層が「線」で作られ、面（色の階調）で作られていない**ため、どの要素も同じ重さに見える。
3. **画面の情報の密度が低く、状態が一目で分からない**。一覧の行は罫線だけで、「目安：／報告：／対応：」が左右に散り、状態は文字の「― 未」「○」だけ（形・色の階調が弱い）。数値は 1 か所にもまとまっていない。
4. **同じ形の箱の敷き詰め**。選択肢（類型 9 個）は 1 つずつ枠で囲まれ、説明が 2〜3 行ずつ常時展開される。`/` の「収録している規制とデータ」も同じ形のカード 6 枚。優先度の差が形に出ない。
5. **ナビが「一覧のリンク集」**。下メニュー（5 項目）と、`/ops/more` の大きな 2 列のリンク集。PC でも、幅 896px（`max-w-4xl`）の細い 1 本の列で、デスクトップの広さを使わない。

画面ごと：

| 画面 | LP ぽいところ（3〜5 行） |
|---|---|
| `/`（判定） | 見出し「そらばん」が 48px、2 文のリード、運航管理の注記、運営者・範囲・地域の表、免責の左線札、ドローンの線画——**判定の入口（地図・入力）に着くまでに 1 画面分スクロール**（375px）。下に「収録している規制とデータ」（説明文＋同形のカード 6 枚）、免責、長い出典のフッター。構成が「紹介→使う→出典」の LP そのもの。 |

## 2. 方向：「航空日誌の紙面」×「業務ダッシュボード」

**一言で**：罫線と地色の差で構造を作り、数値と状態を一目で見せ、操作を速く、余白と動きに品を持たせる。Linear・Vercel の「密度と速さ」に、航空日誌（記入欄・罫線・印）の「紙の落ち着き」を合わせる。影・ガラス・光る枠・丸いアイコンの機能紹介のような構成は使わない。

原則（8 つ）：

1. **構造は罫線と地色で作る**。背景（app）→ 面（surface）→ 沈んだ面（sunken）の 3 階調と、1px の罫。影と半透明は使わない（浮くもの＝ダイアログ・メニュー・ポップオーバー・トーストも、1px の濃い罫と不透明の面で表す）。左線の札・点線の囲み・方眼は使わない。同じ幅のカードを並べず、細い罫線と余白で区切る。
2. **色数は絞る**：紙色の中立色（わずかに温かい）＋アクセントは藍 1 色＋意味の色（成功・注意・危険・情報・中立）。それ以外の色を作らない。
3. **情報の優先度で形を変える**。主役（今日の運航）は大きく、副次（予定、一覧）は密に、補助（凡例・出典）は小さく。**同じ形のカードを敷き詰めない**（1 画面にカードの形は最大 3 種）。
4. **操作が先、説明は後**。説明は §5 の 4 つの置き場所（ⓘ・折りたたみ・詳細パネル・空の状態）へ。ただし固定の注意書きは常に見える（§5.2）。
5. **状態は色・形（アイコン）・文言の 3 つで示す**（WCAG 1.4.1）。色だけにしない。
6. **速さ**：キーボード（コマンドパレット、ショートカット）、並べ替え、保存済みのビュー。実際に動くものだけ（§4）。
7. **動きは 200〜300ms で、必要なときだけ**。押下は拡大しない。`prefers-reduced-motion` を尊重する（動きを止め、意味は静止状態で伝わる）。
8. **現場モードは別系統**。大きさ（56px）とコントラスト（7:1）の基準を維持し、半透明・ぼかし・小さな部品を持ち込まない。

### 2.1 phase-atlas との関係：取り入れるもの・寄せるもの・持ち込まないもの

phase-atlas は、地図が主役の**ワークスペース**（左右のペイン＋地図。スマホではボトムシート＋下タブ）、等幅の数値、細い罫線と深い階調、高い情報密度を持つ。

| 区分 | 内容 |
|---|---|
| **取り入れる（構造・密度・操作感）** | ① 地図中心のワークスペース：≥1024 は左右のペイン＋地図、<1024 は**ボトムシート（peek／half／full の 3 段階）＋下タブ**（`BottomSheet.tsx`・`BottomTabBar.tsx` の作法）。② ペインの端のトグルと「最大化」（`PaneEdgeToggles.tsx`・`WorkspaceControls.tsx`。`[` `]` のキー）。③ ドロワー（詳細・設定を地図の上に重ねる）。④ 等幅の数値（`tnum`）、細い罫線と階調の深さ、情報密度の高さ。⑤ 状態の強調の節度（発光は「選択中」「注意」だけ。常時の発光はしない）。⑥ 作法：`safe-area`、`100dvh`、`prefers-reduced-motion`、タップ領域 44px、フォーカスのリング。 |
| **紙面に寄せる（質感・色・形）** | 蛍光グリーンの計器色をやめ、**紙色の地・墨色の文字・藍 1 色**。角丸は 5px の 1 種類、影なし、半透明なし、システムフォント（日本語 1 種類）、200〜240ms の動き。**文字間隔の広い大文字の小見出し（`letterSpacing 0.18em`）と、測量の格子線の背景は取り入れない**（「LP・冊子ぽさ」の主因と同じ系統のため）。 |
| **明・暗の両対応**（phase-atlas は暗のみ） | そらばんの現場は屋外の明るい場所が多く、事務所では暗い配色も使われるため、**明・暗の両方を第一級**にする。 |
| **持ち込まない** | phase-atlas の依存（`three`・`recharts`・`leaflet`・`jspdf`・`xlsx` など）。そらばんは現行の `maplibre-gl` と自作の部品で足りる範囲にとどめる（増やす場合は理由を述べる）。コードの複写。蛍光色・暗色一本の配色。 |
| **最も参考にする画面** | 地図のある画面：`/`（判定）と `/ops/places`（地点）。運航管理のほかの画面は、サイドバー＋トップバー＋ダッシュボード／表を基本にし、**詳細は右のインスペクタ（ドロワー）**にする。 |

## 3. デザインシステム

### 3.1 色

トークンは CSS 変数（`apps/web/src/app/globals.css`）。**新しい名前**で定義し、移行中は旧名（`paper`・`ink`・`brand`・`signal`・`verdict`・`rule`）を新しい値へ写像する（§10）。コントラスト比は WCAG の相対輝度で計算した実測（`design-tokens.test.ts` が同じ計算で守る）。配色は 1 組だけ（配色案の切り替えはない）。

**中立色（明）**：紙色。わずかに温かい。

|---|---|---|---|
| `bg-app` | #F1EDE1 | アプリの背景 | — |
| `bg-surface` | #FBF9F3 | カード・パネル・入力欄の紙片 | — |

| `line` | #D8D1BD | 区切り線（1px） | — |

### 3.2 タイポグラフィ

**推奨：システムフォントを主にし、Web フォントを減らす（原則ゼロにする）。**

```
--font-sans: -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Hiragino Kaku Gothic ProN",
             "Yu Gothic UI", "Yu Gothic", "Meiryo", "Noto Sans JP", "Noto Sans CJK JP", sans-serif;
--font-mono: ui-monospace, "SF Mono", Menlo, Consolas, "Noto Sans Mono CJK JP", monospace;
```

| 観点 | システムフォント主体（推奨） | 現行（Fraunces・IBM Plex Sans JP・IBM Plex Mono） |
|---|---|---|
| 質感 | Mac・iPhone で SF Pro とヒラギノ角ゴ。Windows は Yu Gothic UI、Android は Noto | 全端末で同じ見え方。ただし Fraunces（欧文の明朝）は「冊子・LP」の主因の 1 つ |
| 可読性 | 日本語は OS 標準が最適化済み。Windows の Yu Gothic UI は細く見えるため、太さは 400／500／600 に限り、本文の太さを 400 未満にしない | Plex Sans JP は読みやすいが、細い太さ（300）の見出しが弱い |
| 表示速度 | Web フォントの取得 0 件（日本語の分割ファイルが多数減る。LCP・文字の入れ替わりのずれが減る） | 取得あり（`display: swap` による入れ替わり） |
| ライセンス | OS 標準のため問題なし | 3 つとも OFL（問題なし） |
| 弱点 | 端末ごとに字面が違う。評価環境（Linux）では Noto で描かれ、**SF での見え方は実機でしか確かめられない**（ユーザー作業 U1） | 一貫するが重い |

数値・ID・座標は `font-variant-numeric: tabular-nums` と等幅（`--font-mono`）。PDF は既存の同梱フォント（Noto）のままで変えない。**確定はデザインの見本の確認ゲートで**（ユーザーが実機で見る）。

寸法（4px 基準）：

| 役割 | 通常（<1024／≥1024） | 太さ | 行の高さ |
|---|---|---|---|
| ページ見出し（h1） | 22／24px | 600 | 1.4 |
| 節の見出し（h2） | 17／18px | 600 | 1.45 |
| 小見出し（h3）・カードの見出し | 15／15px | 600 | 1.5 |
| 本文 | 15／14px（入力欄は 16px 以上。iOS の拡大を避ける） | 400 | 1.7 |
| 表・一覧の文字 | 14／13px | 400 | 1.7 |
| 補助（注記・凡例） | 12px 以上 | 400 | 1.7 |
| 統計の数値 | 28〜34px（等幅・tabular） | 600 | 1.1 |

見出しは控えめ（細い大きな明朝をやめる）。小見出しの大文字＋字間の `eyebrow` は廃止（日本語の見出しにはそのまま使わず、必要なら通常の 12px の補助文字）。字詰め（`palt`）は見出し・ラベルだけ。本文・表では使わない。現場モードは本文 18px 以上、状態の語 20px 以上で太く（12e の基準を維持）。

### 3.3 余白とグリッド

- 間隔は 4px 基準（4・8・12・16・24・32・48）。ページの左右の余白は 16（<640）／24（<1024）／32（≥1024）。
- **アプリの枠（≥1024）**：左のサイドバー 240px、右にトップバー（高さ 56px）と本文。本文は最大 1280px（ダッシュボード・一覧）／ 760px（入力フォーム。長い読み物・詳細は 720px）。12 列、間隔 24px。1280 以上では右に詳細パネル（320〜360px）を開ける。
- 一覧・フォームが細い 1 列（現行の 896px）で終わらないよう、広い画面では 2 列（フォーム＋右の目次／要約）にする。
- 区切りは線より余白と面の差を先に使う。

### 3.4 形：角丸・影・線・半透明

| 要素 | 値 |
|---|---|
| 角丸 | **5px の 1 種類**（`--r-journal` の 1 か所。`rounded-ctl` だけを使う）。ピル（`--r-pill`、999px）は件数の小さなバッジだけ。旧 `rounded-sharp`（2px）は移行中 5px へ写像 |
| 影 | **使わない**。カード・ボタン・入力欄・メニュー・ダイアログ・トースト・シートはすべて影なし。層の違いは、1px の罫（浮くものは `line-strong`）と地色の差で表す。モーダルの背後だけ、ページを暗くする幕（`--scrim`）を敷く |
| 線 | 区切りは 1px。**入力欄・ボタンの境界は 1px の `line-strong`（3:1 以上）**。入力欄は、紙の地より明るい紙片に罫を引いた記入欄 |
| 半透明＋ぼかし | **使わない**。固定のバー（トップバー・下メニュー・保存バー・ペインの端のトグル）もシート・メニューも不透明の面。`backdrop-filter` と `--glass-*` はない |
| グラデーション | 使わない。スパークラインも線だけ（面の塗りなし） |
| フォーカス | 2px の `accent` の輪郭（光る枠・影は使わない）。入力欄では輪郭に加えて罫が `accent` になる |


### 3.5 動き

- 既定は 200ms の `cubic-bezier(0.2, 0.8, 0.2, 1)`（出る：ease-out）。シート・ダイアログの出入りは 240ms（フェード＋ 8〜16px のスライド）。ホバー・押下の色の変化も 200ms。押下は拡大せず、濃い地と 1px のずれで示す。
- 動かすのは「出入り」「状態の切り替わり」だけ。装飾の動き（パララックス、ループ、バウンス）は作らない。
- `prefers-reduced-motion: reduce` では、移動・拡縮をやめ、フェード（または即時）にする（現行の全体指定を維持）。

## 5. 情報設計：説明の置き場所

### 5.1 4 つの置き場所

| 置き場所 | 使う場面 | 例 |
|---|---|---|
| ① 小さな説明（ⓘ） | 用語・入力欄の補足（1〜2 文）。読まなくても操作できるもの | 役割の説明（`ROLE_DESCRIPTIONS`）、「判定の日時（JST）」の意味、列の意味 |
| ② 折りたたみ（「説明」「詳しく」） | 3 文以上の説明、選択肢ごとの長い説明、出典・収録データ・参考 | 事象の類型の説明（選ぶと開く）、収録している規制とデータ、出典のフッター、通信の説明（現場） |
| ③ 詳細パネル（右・シート） | 項目を選んだあとに必要な情報 | 一覧の行のプレビュー、版の履歴、判定スナップショットの根拠 |
| ④ 空の状態 | データがないときだけ、次の操作と一緒に | 「まだ飛行計画がありません。作成すると…」 |

### 5.2 固定の注意書き（**常に画面から到達でき、必要な場面では常時見える**）

**文言の定数は変えない。置き場所と見た目だけを変える。** 折りたたみ・ⓘ・ホバーの中に入れない。「注意バー」（面の色付きの 1〜2 行の帯。ページ見出しの直下）または、該当する項目の真下の補足（11〜13px ではなく 12px 以上）に出す。

| 固定の文言 | 置き場所（常時見える） | 変える点（見た目だけ） |
|---|---|---|
| G1（事故の最初の案内。12e） | 事故・ヒヤリハットの入力画面（事務所・現場）の最上部、入力欄より前（DOM の順でも）。注意（warn）の面の 1 枚の囲み | 番号つきの 3 段落を 1 枚の warn 面にまとめる（黄色い帯＋丸番号をやめる）。文言・順序は同じ |
| N1（事実の記録の注意） | 事故・ヒヤリハットのすべての画面。ページ見出しの直下の注意バー | 左線の札をやめ、info 面の 1〜2 行の帯 |
| N2（公式の手続き） | 一覧・詳細・報告の記録・簡易記録の完了後。N1 と同じ注意バーの 2 段目 | 同上 |
| N3（報告の記録は利用者の申告） | 報告の記録のフォーム・記録の表示の中、項目の真下 | 小さな info の補足（12px 以上）。ⓘにしない |

| 判定の免責（`site-disclaimer`、`PLAN_JUDGEMENT_DISCLAIMER`、`DEFAULT_DISCLAIMER`） | `/`：判定の入口（地図・入力）のすぐ上。運航管理の計画・今日：該当の結果のすぐ下 | 左線札をやめ、neutral 面の帯 |

| 運営者・利用の範囲・対象地域（`site-facts`）、`site-lead`、`site-ops-note` | `/`：常に見える。小さく、1 行〜2 行の帯・チップに | 文言とテストの識別子は変えない。LP の見出しではなく、概要の帯 |

### 5.3 説明の移し先（画面別の方針）

| 現在の説明 | 移し先 |

- 「スキップリンク」（本文へ）を先頭に置く。

### 6.2 スマートフォン・タブレット（<1024px）

- 薄いトップバー（画面名・戻る・利用者メニュー・検索）＋**下メニュー 5 項目**（今日・判定・計画・日誌・その他。12c と同じ行き先）。半透明、高さ 56px 以上（`safe-area-inset-bottom`）。現在地は塗りのピル＋文字の太さ＋ `aria-current`。
- 「その他」は iOS の設定アプリのような**グループ化された一覧**（運航・記録・登録・管理）と、下にログイン中の利用者・ログアウト。
- 保存・送信の主操作は画面下の**保存バー**（不透明、下メニューの上。長いフォームのみ）。

### 6.3 現場モード・サインイン・アクセス権なし

シェル（サイドバー・トップバー・下メニュー）を出さない（現行の `navHiddenOn`）。現場モードは別系統（§3.1 現場、§3.4 半透明なし、56px のタップ領域）。

### 6.4 「今日」はダッシュボード

構成（≥1280。12 列）：

1. ページ見出し「今日」＋日付＋右に主ボタン「＋ 新規」（飛行計画・飛行記録・日常点検・事故の記録。権限のあるものだけ）。
2. **今日の運航**（主カード。8 列）：時間（等幅の大きな数字）、名称、**進行の帯**（判定→通報→確認→携行品の 4 つの小さなステップ。それぞれアイコン＋文言＋状態）、機体・操縦者（副次）、主ボタン 1 つ。運航票（帳票）調をやめる。
3. **数値の要約**（右 4 列。**同じ形のタイルを並べない**：先頭の 1 つ「次にやること」は大きく、残りは縦の一覧の行）：「次にやること」（`nextActionTotal`）、「今日の飛行」、「飛行中」、「日誌が未記入」。**既存の `getToday` の結果から導ける数だけ**を出す（新しい集計 API・DB は作らない）。
4. **次にやること**（表。急ぐ順。緊急度の印＋動詞で始まる 1 行＋行の操作）。
5. **今日の残り・今後の予定**（時間順の行）。7 日先までの予定は、`getToday` の導出に読み取りだけを足す場合に限る（できれば。変更は契約の一覧に書く）。
6. 免責（判定は目安。通報・申請は DIPS で。12c の文言）は面の帯。

件数だけのタイルは 12c で意図的に避けた（「件数が多い画面」にしない）。今回のタイルは**行き先（該当の一覧）を持つ**ことと、**数値の隣に状態のアイコンと文言**を持つことを条件とする。

## 8. 品質の基準（すべての段階）

- **幅**：375・768・1280px で横スクロールなし（`scrollWidth ≤ clientWidth`）。
- **配色**：明・暗の両方。通常の文字 4.5:1 以上、入力欄・ボタンの境界・アイコンの意味を担う部分は 3:1 以上、現場モードは本文・主要ボタン 7:1 以上。
- **操作**：キーボードですべて操作でき、フォーカスが常に見える（2px のリング、アクセント。オフセットは面の色で抜く）。タップ領域は通常 44px、現場 56px 以上。
- **色だけにしない**：状態はアイコン（形）＋文言＋色。
- **文言**：穏当（責める語を使わない。「違反」「過失」「不注意」「落ち度」「処分」「罰則」）。固定の文言は変えない。禁止語（12a〜12e）を新しい文言に含めない。
- **AI らしさの回避**：装飾のためだけのグラデーション、ガラス・影・光る枠、同じ形のカードの敷き詰め（1 画面にカードの形は最大 3 種。同じ幅を並べない）、丸いアイコンを付けた機能紹介のような構成、意味のない絵文字・アイコンの羅列、中央揃えの大きな見出し＋ 3 列のカード、全部が浮く・拡大するホバー、をしない。情報の優先度で、大きさ・面・密度を変える。evaluator は「この画面から 1 つ装飾を取り除いても情報は減らないか」を確かめる。
- **性能**：Web フォントの取得 0（推奨案の場合）、アイコンは外部取得なし、ぼかしはバーだけ。`/` の LCP・レイアウトのずれ（11b の検査）を悪化させない。
- **LP ぽさの測定**：初期表示（375×812・1280×800）で、**操作できる部品（入力・ボタン・リンク・行）が画面の面積の過半に入る**。見出しから最初の操作部品までの間に、固定の注意書き（注意バー）以外の説明の段落（40 字超の `<p>`）がない。evaluator が目視で確かめる。

## 9. 実装メモ（generator・designer 向け）

- Tailwind v4（`@theme inline`）。新しいトークンを `@theme` に追加し、**スコープ方式**で移行する：`.ds`（`ops/layout.tsx` と見本の根に付ける）の下で旧名（`paper`・`ink`・`brand-*`・`signal-*`・`rule`・`rounded-sharp`）を新しい値へ写像する。未移行の画面（`/` など）は、段階 4 まで旧い見た目のまま。段階 5 の最後に旧名・紙の方眼・`eyebrow`・`bearing-mark`・`contour-rule`・Fraunces を削除する。
- `color-scheme: light dark` を宣言し（ラジオ・チェックの暗い配色の問題＝12e の軽微な指摘②の解消）、手動のテーマは `html[data-theme]` で上書きする。初期表示の前に適用するインラインのスクリプトで、ちらつきを防ぐ。
- 依存を増やさない（アイコン・コマンドパレット・シート・ポップオーバーは自作。ネイティブの `<dialog>`・`popover` 属性・`<details>` を活かす）。チャートは使わない（スパークラインはインライン SVG）。増やす場合は理由を `sprint-12g.md` に書く。
- Next.js 16 の破壊的変更：実装前に `apps/web/node_modules/next/dist/docs/` の該当の文書（フォント、レイアウト、`next/script`、`Suspense`）を読む（`apps/web/AGENTS.md`）。
- 新しい部品は、既存の `data-testid`・DOM の順序（G1 が入力欄より前）・`aria-*` を保つ。**部品の置き換えは「見た目の層」だけで、状態・API 呼び出し・送信待ちの仕組みを変えない**。
