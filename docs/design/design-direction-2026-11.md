## ドローン飛行管理アプリ デザイン方針書

Dronboの操作録画から読み取れたデザインの傾向を参考にしつつ、より洗練された独自のデザインに発展させるための方針書。Claude Code側の開発に渡す前提で、数値は実装時にそのまま使える形で書く。

### 0. この文書の扱い

- 録画は縮小したコマ抜きのため、色・余白・フォントの正確な値は読み取れていない。第1章は「観察できた傾向」、第2章以降は「こちらで新しく決める独自仕様」として分けている。
- Dronboの画面・ロゴ・文言・アイコン・配色をそのまま使わない。傾向を参考にし、数値・配色・文言はすべて独自に定義する。
- 対象は iPhone縦画面(録画は 1180×2556px)。まずモバイル優先で、のちにWeb版へ広げる。

### 1. Dronboの観察できた傾向(参考)

全体の印象

- 白地ベースで、情報量が多い業務アプリ。カードを縦に積む構成が中心。
- 下部に5項目のナビ、画面上部にタブ(案件管理・飛行計画・飛行日誌・機体・携行資料)を置く二段構造。
- 有料機能はバッジで示し、無料枠は使用回数/上限で見せる。

カードと余白

- カードは角丸で、背景より少し明るい面に薄い境界か影で浮かせている。
- 状態(待機中・飛行中・飛行済)は色付きの小さなラベルで区別している。
- 通報フォームは1画面を縦にスクロールする長い構成で、セクションごとに見出しで区切る。

弱点として感じた点(発展の余地)

- 長いフォームで、現在どこまで入力したかが分かりにくい。
- 調査結果(標高・気象・ハザード)が文字中心で、危険度が一目で伝わらない。
- 有料バッジや使用回数の表示が各所に散り、情報の優先順位が揺れる。
- エラー(特定飛行の未選択)が送信後に出るため、入力中に気づけない。

### 2. デザインコンセプト

コンセプト:「静かな管制室」 空と地図を主役にし、UIは一歩引く。危険・注意・安全の判断が3秒で伝わる、落ち着いた計器盤のような見た目にする。

3つの原則

1. 判断を先に見せる:飛べる/注意/飛べないを最初に大きく示し、根拠は下に畳む。
2. 入力は分割する:長い1画面フォームをやめ、段階ごとの短い画面にして進捗を示す。
3. 装飾は色を絞る:色は意味(状態)にだけ使い、飾りには使わない。

### 3. カラー設計

数値はすべて独自に決めた案。実装時はデザイントークン(CSS変数)として定義する。

ベース(明るいテーマ)

- 背景:#F6F7F9(わずかに青みのある薄いグレー)
- 面(カード):#FFFFFF
- 面の一段上(入力欄・選択状態の下地):#EEF1F5
- 境界線:#E1E5EB(1px)
- 文字・主:#14181F
- 文字・副:#5B6573
- 文字・淡(補足・無効):#8A93A1

ブランド色(1色だけ)

- 主色:#1F5FE0(深めの空色)。主要ボタン、選択中のタブ、リンクにだけ使う。
- 主色の薄い面:#E8F0FD(選択状態の背景)

状態色(意味専用。飾りに使わない)

- 安全:文字 #17794A / 面 #E6F4EC
- 注意:文字 #9A5B00 / 面 #FDF1DC
- 危険・飛行不可:文字 #B42318 / 面 #FDE8E6
- 情報・待機:文字 #3F4B5E / 面 #EAEEF3
- 飛行中:文字 #0E6B8C / 面 #E1F2F8

暗いテーマ(屋外・夜間の使用を想定)

- 背景:#0E1116、面:#161B22、面の一段上:#1E2530、境界線:#2A3240
- 文字・主:#EDF0F4、文字・副:#9AA4B2
- 主色:#6B9BFF、状態色は明度を上げて同じ色相を使う
- 屋外の直射日光では明るいテーマの方が読みやすいため、初期設定は自動(端末設定に追従)にし、手動で切り替えられるようにする。（→ D2 により休眠）

使い方のルール

- 1画面で使う有彩色は、主色+状態色のみ。
- 状態は色だけで伝えず、必ずアイコンと文字を併記する(色覚の差への配慮)。
- 文字と背景のコントラスト比は、本文4.5以上、大きな文字3以上を守る。

### 4. タイポグラフィ

フォント(Webフォントの読み込みは軽さ優先)

- 日本語:Noto Sans JP(ウェイト400・500・700の3つだけ読み込む)
- 英数字・数値:Inter(数値は tabular-nums を有効にして桁を揃える)
- 代替:system-ui, -apple-system, "Hiragino Sans", sans-serif

サイズ(iPhone基準、単位px)（→ D3 の読み替えを適用）

- 画面タイトル:24 / 行間1.35 / 700
- セクション見出し:18 / 行間1.4 / 700
- カード見出し:16 / 行間1.45 / 600
- 本文:15 / 行間1.65 / 400
- 補足・ラベル:13 / 行間1.5 / 500
- 最小:12(これより小さくしない)
- 数値の強調(風速、標高、残り日数):28〜34 / 700 / tabular-nums

ルール

- 字間は日本語本文で0.01em、見出しで0.02em。
- 1行の長さは、スマホでは画面幅いっぱいでよいが、Webでは全角38文字前後で折り返す。
- 太字は見出しと数値だけ。本文中の強調は色ではなく500のウェイトで行う。

### 5. 余白・グリッド・角丸・影

スペーシングの基準(4pxの倍数のみ)

- 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
- 画面の左右余白:20
- カードの内側余白:16(密な一覧は12)
- カード同士の間隔:12
- セクション間の間隔:32
- タップできる要素の最小サイズ:44×44(手袋を想定する屋外用の主要ボタンは56)（→ D3 で 48）

角丸

- カード:16
- 入力欄・ボタン:12
- 小さなラベル(状態バッジ):999(完全な丸み)
- 地図の上に重ねるパネル:20(上側のみ)
- 角丸は上の4種類に限定し、画面ごとに別の値を作らない。

影と境界

- 基本は影を使わず、1pxの境界線で面を分ける。
- 浮いて見せるもの(下部ナビ、地図上のパネル、ボトムシート)だけ影を使う。
- 影:0 -4px 24px rgba(20,24,31,0.08)(上方向に落とす)
- 暗いテーマでは影をやめ、面の明度差で分ける。

アイコン

- 線の太さ1.75px、角は丸め、サイズ20/24の2種類。
- 塗りつぶしは選択中の状態だけに使う。

### 6. 画面構成と情報設計

全画面を「上に状態、真ん中に主役、下に操作」の三層で組む。Dronboの五つ並びの下部ナビと上部タブの二段構えは、現在地が分かりにくくなるため、下部ナビ一段に統合する。

下部ナビ(4項目)

- ホーム / 計画 / 日誌 / 機体と書類
- 学習・ニュース・相談はホームの下段にカードとして置き、常時表示しない。
- 高さ64(安全領域を除く)。選択中は主色のアイコンと文字、背景は主色の薄い面。

ホーム画面の構成(上から順に)

1. 現在地と日付(補足サイズ)
2. 判定カード:今日の飛行判定を一枚で示す。最上段・全幅・高さ約160。「飛行可 / 注意 / 不可」を28pxの太字とアイコンで表示し、その下に根拠を一行ずつ(風速、降水確率、飛行禁止区域、日没までの残り)。（→ 文言は上の「調整」に従う）
3. 次の予定:直近の飛行計画一件。状態ラベル、日時、場所、地図サムネイル。
4. 期限アラート:許可承認、機体登録、技能証明、保険のうち残り60日以内のものだけを横並びで表示。なければこの段は出さない。
5. クイック操作:飛行前点検、新規計画、飛行記録の三つ。幅を三等分したボタン。

計画作成は6ステップに分割

1. 場所(地図で飛行エリアを描く)
2. 日時
3. 自動調査の結果確認
4. 目的と運航条件
5. 操縦者・機体・許可(事前設定から呼び出し)
6. 確認して通報

- 上部に細い進捗バー(高さ4、主色)とステップ名を固定表示する。
- 各ステップの末尾で、そのステップの入力漏れを検証し、次へ進む前にエラーを出す。送信時にまとめて怒らない。
- 「戻る」で入力が消えないよう、全入力を下書きとして自動保存する。（→ 端末に個人情報を残さない形で）
- 最後の確認画面は、入力内容を読み取り専用のカードで並べ、各カードに「修正」リンクを付ける。

### 7. コンポーネント仕様

ボタン

- 主ボタン:高さ52(屋外用は56)、角丸12、背景は主色、文字は白、太さ600。
- 副ボタン:背景は面の一段上、文字は主文字色、境界線1px。
- 文字ボタン:背景なし、主色の文字。高さは44を確保。（→ 48）
- 危険操作(削除):副ボタンの形で文字だけを危険色にし、確認ダイアログを必ず挟む。
- 無効状態:背景 #EEF1F5、文字 #8A93A1。理由が分かる場合は下に一行で理由を書く。
- 押下時:明度を6%下げ、スケール0.98。120ms。

カード

- 通常:背景白、角丸16、境界線1px、内側余白16。
- 判定カード:状態色の薄い面を背景にし、左端に6pxの状態色の帯を付ける。帯は角丸に沿って切る。
- 一覧カード:高さは内容に合わせ、最小72。タップ領域はカード全体。
- カード内の階層は、見出し→主情報(数値や日時)→補足の三段までとする。

状態ラベル

- 高さ24、左右余白10、完全な角丸、文字13/600。（→ 28 / 14）
- 待機中=情報、飛行中=飛行中色、飛行済=安全色の薄い版、中止=危険色。
- 先頭に8pxの丸を置き、文字と併記する。

入力欄

- 高さ52、角丸12、背景は面の一段上、境界線なし。フォーカス時に主色の2px枠。
- ラベルは入力欄の上に常時表示(プレースホルダーをラベル代わりにしない)。
- エラー時は枠を危険色にし、下にアイコン付きの一行で理由を書く。
- 日時選択はiOS標準のピッカーに任せず、30分刻みのクイック選択を先に出す。

チェック項目(飛行前点検)

- 一行72、左に大きな丸いチェック(32)、右に項目名。行全体がタップ領域。
- 項目は系統ごとにグループ化して折りたためるようにし、グループ見出しに「完了数/総数」を出す。
- 全項目が埋まるまで保存ボタンは無効のままにせず、未完了数を表示して押せるようにし、押したら未完了グループへスクロールする。
- 触覚フィードバックは、チェック時に軽く一回、全完了時に成功の一回。

ボトムシート

- 地図上の詳細表示と、選択肢の提示に使う。上側の角丸20、つまみ(幅36・高さ4)を中央上部に置く。
- 高さは3段階(ピーク120 / 中間50% / 全面90%)。背景の暗幕は中間以上でのみ表示。

空の状態とエラー

- 空の状態は、アイコンと一文と一つの主ボタンだけにする。説明を長く書かない。
- 通信エラーは画面全体を止めず、該当カード内に再試行ボタンを出す。
- DIPS連携のエラーは、原因(未ログイン / 認証失敗 / 先方の障害)を分けて文言を出し、やり直しの導線を同じ画面に置く。（→ API 接続後）

### 8. 地図まわりのデザイン

地図はこのアプリの主役のため、操作部品を地図の上に溜め込まない。

- 地図は画面全体に敷き、操作は上端の検索欄、右側の縦ツール列(最大4個)、下端のボトムシートに限る。
- ツール列のボタンは44×44の円形、背景は面の色を90%の不透明度、影は上記の浮き用のみ。（→ 48）
- 地図のタイルは、彩度を落とした淡いスタイルにし、飛行エリアと規制区域が最も目立つようにする。
- 飛行エリアの塗り:主色の18%、輪郭は主色2px。頂点は直径14の白丸で主色の縁。
- 規制区域の塗り:危険色の14%、輪郭は危険色1.5px(破線)。空港周辺・DID・緊急用務空域は線種と塗りの模様で区別し、色だけに頼らない。
- 描画中の面積表示は、図形の中心に小さなラベルで出す。
- エリア上限を超えそうなときは、超える前に輪郭を警告色に変え、数値で残りを示す。
- 屋外の強い日差しを想定し、地図上の文字は縁取り付きにして可読性を保つ。

### 9. 自動調査結果の見せ方(発展の中心)

Dronboでは文字と数値の羅列になりがちな調査結果を、判定→根拠→詳細の三層にする。

- 第1層:総合判定(飛行可 / 注意 / 不可)を一語と色とアイコンで示す。
- 第2層:項目別の判定を、法令・空中・地上・気象・標高の五つの小さなタイルで並べる。各タイルは状態色の丸と一語の結果だけを出す。
- 第3層:タイルをタップすると詳細がボトムシートで開く。数値、根拠、参照元、取得時刻を出す。
- 気象は時間別の風速をスパークライン(折れ線)で示し、飛行予定の時間帯を帯でハイライトする。風速の閾値を超える時間は線を危険色に変える。
- 標高は断面図(横軸=距離、縦軸=標高)にし、飛行エリアの高低差を一目で見せる。
- 取得に失敗した項目は「未確認」として灰色で示し、安全と誤認させない。
- 全ての調査結果に取得時刻を付け、古くなった結果は再取得を促す。

### 10. 動きとフィードバック

動きは「状態が変わったことを伝える」ためだけに使い、飾りには使わない。

- 標準の長さは180ms、イージングは ease-out(cubic-bezier 0.2, 0, 0, 1)。
- 画面遷移:横スライド240ms。ボトムシートは下から280ms。
- 数値の更新:前の値から新しい値へ、桁を揃えたまま200msで切り替える。
- 判定カードの状態が変わるときは、背景色のみを300msでなめらかに切り替え、ポップアップや点滅は使わない。
- 読み込み中は、スピナーではなく、カードの形をしたスケルトン(薄い灰色の帯)を出す。1.2秒周期でゆるく明滅させる。
- 端末の「視差効果を減らす」設定が有効なときは、スライドを廃止してフェードのみにする。
- 触覚:チェック・保存・送信完了で軽い振動。エラーでは振動を使わない(屋外で誤作動と混同しやすいため)。

### 11. アクセシビリティと屋外利用

- 文字は端末の文字サイズ設定に追従する。最大の拡大でもレイアウトが崩れないよう、固定高のカードを作らない。
- 状態は色・アイコン・文字の三つで必ず伝える。
- タップ領域は44×44以上。手袋を想定する飛行当日の画面では56以上を優先する。（→ 48 / 56）
- 直射日光下で読めるよう、本文のコントラスト比は7以上を目標にする(最低でも4.5)。
- 片手操作を前提に、主要な操作は画面下半分に置く。
- スクリーンリーダー用に、判定カードは「飛行可、風速3メートル、降水確率10パーセント」のように一文で読み上げられるラベルを付ける。
- 日本語の約物と数字の間に不自然な空きが出ないよう、フォントの文字詰め(palt)は見出しにのみ適用する。

### 12. 他のサービス・サイトへの展開

このデザインは、ドローン関連の複数のサービスやサイトに流用できるよう、部品と数値を共通化する。

- 共通部分:色・文字・余白・角丸・影・状態ラベル・カード・入力欄・ボタンはすべてデザイントークンにまとめ、一つのパッケージとして各サービスから読み込む。
- サービスごとに変えるのは、主色の一色と、ロゴ・アイコンの絵柄だけにする。たとえば、飛行管理は空色、点検・整備は深い緑、顧客向けの案件管理は墨色を主色にする。
- Web版(PC)では、画面を左のナビ(幅240)・中央の主領域・右の詳細パネル(幅360)の三分割にする。スマホで下部シートだった詳細は右パネルに置き換える。
- ブレークポイントは、600(スマホ→タブレット)と1024(タブレット→PC)の二つのみ。
- ランディングページ(紹介サイト)は、余白をアプリの約2倍に広げ、見出しを40〜56で大きく見せる。ただしカード・色・角丸は同じ規則を使い、アプリとの一貫性を保つ。

### 13. Claude Code側への実装指示

進め方

1. 色・文字・余白・角丸・影を、CSS変数(デザイントークン)として一つのファイルに定義する。以降、画面側に数値を直接書かない。
2. ボタン、カード、状態ラベル、入力欄、チェック行、ボトムシート、スケルトンを、トークンだけを使う部品として先に作る。
3. 部品の一覧を見られる確認用ページ(スタイルガイド)を作り、明るい・暗いの両テーマで目視確認する。（→ D2 により明るいのみ）
4. ホーム→計画作成→飛行前点検→日誌の順に画面を組む。
5. 実機(iPhone)の画面幅 390 と 430 で、文字サイズを最大にした状態も確認する。

守ること

- 他社アプリの画像・ロゴ・文言・アイコン・配色をそのまま使わない。この文書の数値と文言を出発点にする。
- 色は意味を持たせた箇所にだけ使い、装飾目的のグラデーションや影を足さない。
- 一つの画面に、主ボタンは一つだけ置く。
- 文言は、短く、動詞で終わる形にそろえる(例:「点検を保存」「計画を通報」)。
- 画面ごとに新しい角丸・余白・色の値を作らず、必要なときはまず文書の側に追記して相談する。

未確定として残すもの(実装前に確認)

- 主色の最終決定(空色 #1F5FE0 を仮置き)（→ D1 で確定）
- 日本語フォントの読み込み方式(軽さを優先するか、見た目を優先するか)
- 暗いテーマを初期から作るか、後回しにするか（→ D2 で確定）
- Web版(PC)を最初から作るか、スマホ版を先に出すか
