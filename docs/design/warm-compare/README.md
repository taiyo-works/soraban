# 判定画面のデザイン探索（暖色・ピル型・FINESYSTEM 土台）

2026-10-25。のりさんの「地味で事務的、カクカクで堅苦しい、色に温かみがない」への回答として、同じ判定画面（スマホ 390px・PC 1280px）を 3 方向で作って並べた。アプリ本体（`apps/web/src`）は変更していない。画面の文言は `app/page.tsx`・`regulation-checker.tsx`・`verdict-summary.tsx` に合わせた表示見本で、判定内容（米子市役所の例）は見本用。

| 案 | 一言 | PC | スマホ | HTML |
|---|---|---|---|---|
| A | 角を少しだけ丸める。FINESYSTEM に最も近い | `a-pc.png` | `a-mobile.png` | `a.html` |
| B | 紙の質感・手描きの線・傾いたスタンプ | `b-pc.png` | `b-mobile.png` | `b.html` |
| C | 空と地図の絵本。等高線の丘と雲 | `c-pc.png` | `c-mobile.png` | `c.html` |

3 案を 1 枚に並べた画像は `compare.png`（上が PC 全体、下がスマホの最初の 1300px 分）。

再生成：`node src/build.mjs`（HTML）→ `node src/shoot.mjs`（撮影と、はみ出し・12px 未満・44px 未満の検査）→ `python3 src/compose.py`（比較画像）。配色の検査は `python3 src/contrast.py`。

## 土台（3 案共通。FINESYSTEM から取り入れた点）

- 橙 `#F89B48` を主役にする。使う場所は操作（主ボタンの面、チェックの印、見出し脇の縦線、現在地の印、ホバー）。橙の面に載せる文字は墨 `#262523`（7.13:1）。橙の細い文字は使わない。
- 地は白 `#FFFFFF`、オフホワイト `#F7F7F3`、ベージュ `#EDEDE5` を帯ごとに交互に敷く（ヒーロー=白、判定=オフホワイト、手続き=ベージュ、規制ごとの判定=白、免責=オフホワイト）。
- 文字 `#262523`、プレースホルダー `#68655B`（白の上 5.83:1）、罫線 `#C4C4C4`。
- 影は `0 0 24px rgba(0,0,0,.1)` のみ（B は紙を重ねた段差のずらし影）。
- 角丸は大 16／中 8／小 4、ボタンは完全なピル（9999px）。
- ピルボタン：白 92% の地に 1px の罫、左余白を広く、右端に直径の大きい墨の丸＋白い矢印。ホバー・押下・フォーカスで丸が橙に変わる（主ボタンは橙の面で、丸が白に変わる）。動きは 0.5s の ease-out、`prefers-reduced-motion` で停止。
- 見出し：左 5px の橙線＋背後に巨大な薄い橙の数字（01〜03）。
- 書体：Noto Sans JP＋英数字は Plus Jakarta Sans（このマシンには両方ないため、撮影は代替の IPA ゴシックで、字の太さと数字の形が実機と少し違う）。
- 取り入れなかった点：CTA の桃 `#CC6595` は、白文字で 3.58:1、墨文字で 4.28:1 のため文字を載せられず不採用。紫 `#A2689B` も使っていない。

## 橙（操作）と判定色（結果）の役割分担

橙は「押せる・今ここ」の色、判定色は「結果」の色。判定の印の中や判定の塗りに橙は使わない。判定は色だけに頼らず、形と文言を併用する。

| 判定 | 塗り | 文字 | 形 | コントラスト |
|---|---|---|---|---|
| 飛行不可 | `#A81D28` | 白 | 角丸の四角に× | 7.31 |
| 要手続き | `#EDB800`＋2px の濃い枠 `#6B5800` | 墨 | 三角（!） | 8.35 |
| 手続き済み・情報 | `#262523` | `#F7F7F3` | 丸にチェック | 14.26 |
| 手続き不要 | `#225F36` | 白 | 太い輪（○） | 7.61 |
| 判定不能 | 白＋点線の枠 `#4F5762` | `#4F5762` | 点線の四角に？ | 7.31（白）／6.21（ベージュ） |

琥珀 `#EDB800` と橙 `#F89B48` は近い黄〜橙なので、琥珀は必ず濃い枠と三角の形をつけ、橙は判定の印に使わない。画面下に「判定の見分け方」として 5 種を並べてある。

### ピルを使う箇所（全案共通）

ブロックの角は案ごとの方針のまま。ピルは次の箇所だけで、カード・地図の枠・表・入力欄には使わない。

| 箇所 | 種類 | 高さ |
|---|---|---|
| 「この地点を判定する」 | 主ボタン（橙の面） | 56px |
| 「現在地で判定」 | 副ボタン | 52px |
| 「結果を PDF で保存」「DIPS 2.0 を開く」 | 副ボタン（小） | 48px |
| 規制レイヤーの切替（7 個） | チップ。ON は白＋墨の実線＋橙のチェック、OFF は点線の縁＋空の丸。色だけでなく形で区別 | 44px |
| 判定タグ（要手続き・手続き不要など）と「判定の見分け方」 | 状態タグ（マーク＋言葉）。押せない表示 | 30px |
| 確認日・出典つき・期限・法令区分 | 情報タグ。押せない表示 | 28px |
| 出典の区分（国・県・市）、手続きの番号 | 丸いバッジ（円） | 32／40px |

押せるものはすべて 44px 以上（撮影時の検査で確認）。タグは押せないので 44px の対象外。

## 案ごとの特徴

- **A：角を少しだけ丸める**。FINESYSTEM の形をほぼそのまま使う。橙の等高線と太陽、ドローンの線画だけを添える。装飾が少なく、業務の読みやすさが最も高い。
- **B：手触りのある紙**。紙のざらつき、ちぎれた帯の境、墨の縁と段差の影、手描き風に揺らした線。結論は少し傾いた「要手続き」のスタンプ（マークの三角と文言入り、色は濃い琥珀の墨 `#6B5800`）。地図の上にはからし色のテープ。
- **C：空と地図の絵本**。ヒーローを夕日と丘の層（橙・ティール）と雲の絵にし、地図の枠の角に雲、結論カードの下に丘の縁。ティールと淡い水色が差し色。

## 確認したこと

- 文字の 4.5:1：本文・注釈・プレースホルダー・判定タグ・橙面の墨文字はすべて満たす（`src/contrast.py`）。
- 3 案 × スマホ・PC で、はみ出し・最小文字 12px 未満・押せる部品 44px 未満が 0（`src/shoot.mjs`）。
- 外部通信なし（フォントは端末のもの、画像は SVG の直書き）。

## 注意

- B の紙・揺らした線は SVG フィルター（feTurbulence・feDisplacementMap）で作っている。本実装では、判定画面全体に重ねると描画が重くなるため、背景の紙とスタンプ、見出しの下線に限るのが無難。
- スタンプ（B）は粒状のかすれを入れてあり、文字は最低でも濃い琥珀 `#6B5800` の太線で残る。文言は別にも「結論」欄の隣へ置けるが、見本では省いた（読み上げは `aria-label` で対応）。
- C の ヒーローは縦に約 400px 使う。判定の入口が画面の下に下がるので、業務利用では高さを抑える（200px 程度）案を別途検討したい。
